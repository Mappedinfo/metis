# 证据与决策规则

复盘需要合并多个来源、检验完成声明，或在不同解释与工作流间选择时使用。

## 让证据对应主张

| 主张 | 检查内容 | 单凭这些信号不能证明什么 |
|---|---|---|
| 功能可用 | 相关已接受行为，以及可复现交互或针对性测试 | 提交或构建成功不能证明可用性或已部署 |
| 实验改变了结论 | 运行配置、已完成运行、实际结果及其支持的比较 | 启动器、拟议分析或运行中进程不是结果 |
| 来源改变了论证 | 相关来源段落及其带来的主张或决策 | 引文数量或已下载论文不能证明已阅读或支持某主张 |
| 里程碑已完成 | 每项已接受必需结果及其验收证据 | 检查清单、文件数量或部分成功组件不能证明整个里程碑 |
| 学习者理解了概念 | 学习者实际解释、解题、应用或延迟回忆 | agent 生成的答案不能证明学习者掌握 |
| 自动复盘已交付 | 真实运行、请求产出物、持久状态和承诺的交付界面 | 调度条目或进程零退出不能证明内容已交付 |

为每项重要主张记录证据位置、已知的观察时间、覆盖局限与影响。用户提供的陈述也可以是证据，但应明确归因，不能改称为独立验证。检查承诺的结果，不能仅依赖生成方的成功消息。

## 时间与来源冲突

区分事件时间、观察时间和文件修改时间。当前产出物可能描述旧事件。未提交工作树可能包含请求区间之外的改动。说明解析本地日期边界所用时区；“本周”等措辞会影响结论时，写明准确解释。

来源不一致时保留冲突，选择能支持具体主张的来源。较新的提案不会仅凭时间戳覆盖已接受范围。先检查针对性差异、已接受决策或直接结果，再在不同叙述间取舍。有界补查无法解决时，汇报未决主张和最小辨别性检查，不把不兼容断言取平均。

## 诊断阻塞

对每个重要阻塞记录：

```text
症状：直接观察到什么。
原因：有支持的解释，或相互竞争的假设。
辨别性检查：能区分这些假设的最小观察。
影响：哪项已接受结果仍不可能完成或尚未验证。
解除条件：所需输入、修复、决策或授权。
```

区分未开始、运行中、失败、完成但未验证；区分输入缺失、过时、无效；区分技术依赖与权限限制。反复润色可能回避关键检查，但除非已检查历史支持，否则只能标为解释。

例如导出任务报告成功，但要求的输出不存在。可观察事实是产出物缺失，不能直接认定算法失败。在预算内检查一次输出目标和完成记录；证据尚未区分前，保留其他可能原因。已接受结果仍未验证。

## 从证据形成优先级

优先选择能改变最重要待决策问题、符合已授权时间和范围、且验收可观察的行动。两条工作流竞争时，说明实际取舍。外观调整和基础设施是否有价值，取决于它们对已接受结果的作用；不能自动认定为浪费，也不能自动认定为实质进展。

研究工作要说明具体参考价值：活动支持了哪个问题、机制、比较、主张边界、图或决策。区分直接贡献与仍需建立联系的能力建设。负结果若排除了无依据主张，可以是最有价值的进展。普通工作不强加这一研究视角。

提出优先级时保留必需覆盖范围。延期或删除一项要求需要明确且已接受的变更，不能仅凭 agent 把它在列表中排得较低。最后把选定动作与产出物、检查、依赖和真实状态关联。
