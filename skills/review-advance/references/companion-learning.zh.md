# 复盘中的伴学

任务要求判断应记住什么、复习什么或下一步前应学习什么时使用。仅仅采用日/周节奏，不授权创建持久学习数据库或提醒。公有工作流定义有用的判断；选定的本地适配器定义真实存储 schema。

## 选择值得复习的知识项

只有存在已检查证据且有具体下一次用途时，才保留概念、不变量、方法、公式、已纠正误解或缺失前置知识。不能把打开文件或花费时间算作学习进展。优先少量重要知识项，不把学习台账变成活动档案。

每个候选项需要：

- 稳定主题和来源位置，包括足以核验主张的章节、公式、代码位置或产出物锚点。
- 在某任务或决策中的下一次用途。
- 分开记录来源状态与学习者已展示的理解。
- 可执行的复习提示和合格回答检查方式。
- 下一项任务需要但尚未展示的知识所对应的预习需求。

需要更细分类时，保持各轴独立：`knowledge_type = project | domain | math`，有意义的 snake-case `domain`，以及 `review_mode = teach_back | derivation | problem | transfer`。数学知识项应限定一个公式、等价关系、推导步骤或小型定量对照，并有精确来源锚点；不能把整章内容装入一个掌握条目。将这些概念映射到适配器文档规定的字段，不强制公有存储版本。

## 分清来源有效性与掌握程度

| 轴 | 有用区分 |
|---|---|
| 来源状态 | 已检查来源直接支持；从已支持前提明确推导；未验证假设；附替代证据的已纠正主张 |
| 理解证据 | 接触过；解释过；应用过；延迟后回忆出；误解已纠正 |

记录真正观察到了什么，以及是谁的表现。agent 的正确推导可以支持主张，却不能证明用户能推导。用户回忆成功也不能独立验证来源主张。纠错是有证据的事件，不自动等于最高掌握等级。没有观察到学习者回答时，将检查标为建议或等待回答；不能虚构回忆质量。

## 设计回忆与预习提示

用能暴露具体误解或能力缺口的问题：

- **复述：** 不看来源解释关键区别，再与引用定义比较。
- **推导：** 重建指定步骤并说明允许该步骤的假设；检查中间推理，不只看最终公式。
- **解题：** 解一个能检验该概念的小型新例子。
- **迁移：** 把思想用于不同任务，并指出类比在哪里失效。

预习项说明即将开展的任务、最小必要来源/概念，以及可观察的准备产出，如解释、例子、推导或玩具实现。提出预习项不代表已读来源，也不代表学习者已准备好。

要求复习日期时，使用用户或适配器的间隔策略。间隔检索是操作性启发式，不是掌握的证据，也不是普适记忆定律。回忆良好可能支持延长间隔；部分回忆需要针对性检查；回忆失败需要前置知识或更简单问题。暂停或退休条目须记录相关性理由和重开条件。没有策略时，提出节奏建议，不悄悄创建到期日期。复习日期不等于已部署提醒。

## 持久更新保持可选且可验证

没有已授权存储时，在复盘中交付拟议复习/预习项，不创建备用台账。获准更新时：

1. 在许可根目录内解析 `learning.adapter` 和 `learning.store`；改变状态前检查并验证既有 schema。
2. 使用稳定条目标识，保留历史复习日期与记录，合并新证据但不虚构已完成复习。分类冲突须明确解决，不能悄悄重分类。
3. 将完整拟议批次验证后再提交到存储。重复导入未变内容不能产生重复条目或推进复习计数。存储迁移需单独授权。
4. 回读受影响记录，凭证据汇报真实新增、纠错、复习更新、暂停或退休。验证或写入失败时，保留存储完整并说明解除条件。

学习者知识记录与 agent 自评、skill 质量反馈分开。agent 任务成功不证明用户掌握、满意，也不授权修改未来行为。
