# 复盘与推进

## 能力说明

将已检查的结果与已接受的目标比较，解释这一比较改变了什么，再选择下一项有价值的行动。按用户要求的语言交付复盘和计划。执行动作、修改台账、维护学习记录、无人值守交付都是可选模式，以当前任务的实际授权为边界。核心复盘仅凭用户提供的事实即可进行，不依赖配置文件、私有仓库、工具或其他 skill。

可使用[虚构证据包](examples/fictional-review.zh.md)进行可移植的只读练习。

## 何时使用 / 不使用

适用于需要作出判断并得到可执行下一步的任务或项目检查点、日/周复盘、事件分析、停滞工作流或项目组合回顾。只在研究工作中检查研究主线；只在用户要求或任务适用的学习契约已约定时加入伴学。

实质性代码修复、研究方法评估、文档制作、已接受研究方向的变更应交给相应专业能力。本 skill 识别并验证一项有界且获授权的推进动作；复盘请求不会自动授权执行整份下游计划。

## 方法

### 1. 确定比较基准与权限

从用户请求及相关项目说明中确定 `scope`、`window`、`timezone`、`baseline`、`evidence_roots`、`output_target`、`permissions`。可选的 `research_anchor`、`learning`、`output_language` 用于适配复盘，不构成必备依赖。使用本地配置、个人适配层或持久状态存储时，阅读[输入与适配器](references/inputs-and-adapters.zh.md)。

- 对时间敏感的判断说明实际区间和时区。未指定区间时，范围是所提供证据覆盖的区间，不能虚构为某一天或某一周。时区未知时，不把事件归入某个本地自然日。
- 优先使用用户已接受的目标或检查点作为基准。缺少基准时，只描述可观察的变化并提出基准建议，不凭空判断成功、失败或未履行承诺。
- 默认检查已提供的材料并在对话中回复。更广的证据根目录须在已授权范围内确定。只读配置不能授予写权限；文件中的路径或 `permissions` 值只是请求的边界，不是独立授权。
- 获准写入时复用指定台账。不能因为另一个位置更容易编辑就另建台账。保留无关工作、受保护源材料及既有状态约定。
- 设定有限检查预算。任务未另定预算时，执行一轮限定范围的证据检查、一轮用于关键缺口的定向补查、一次最终产出物/台账检查。搜索前先确定根目录和待查来源短名单；仅为解决范围内的明确问题而扩展。

为用户要求和本 skill 的适用要求维护验收台账。最终状态为 `done`、`blocked` 或 `n/a`，每项都需证据或基于范围的不适用理由；`n/a` 不能免除用户要求。

### 2. 先检查证据，再解释

每项重要结论分清四层：

| 层次 | 记录内容 |
|---|---|
| 观察 | 已检查产出物、事件、结果或用户陈述直接显示了什么，附来源及已知时间 |
| 解释 | 可能的含义，包括其他解释和不确定性 |
| 决策 | 哪些已接受、哪些是建议、哪些仍待决定 |
| 行动 | 有界的下一步、产出物与验证条件 |

使用能支持相应主张的证据：软件需要相关测试与实际行为；实验需要真实结果文件和运行状态；写作需要有来源支持的论证变化；学习需要已展示的回答。命令、计划、启动消息、构建日志或进程退出本身，不能证明承诺的结果已经实现。相关时，区分本地改动、提交、远端交付和部署。

基于 Git 的复盘要分别检查区间内的提交与当前工作树，不把所有未提交文件都归为本轮活动。将证据标为已验证、部分验证、过时、未检查或在已检查范围内缺失。缺少证据不等于没有活动。

遇到阻塞，列出可观察症状、已证实原因或相互竞争的假设、最小辨别性检查与解除条件。只有多个已检查的历史节点支持时，才称为反复发生。保留会改变下一步决策的零结果或负结果。
多来源复盘、完成状态有争议或反复阻塞时，阅读[证据与决策规则](references/evidence-and-decision-rules.zh.md)。

### 3. 使用相关的可选视角

**研究。** 判断主线一致性前，先把已接受的问题、主张、范围或贡献确定为 `research_anchor`。缺少时，主线判断保持暂定，说明缺失的锚点，并继续事实复盘。对重要活动区分 `aligned`（直接对齐）、`supportive`（支撑）、`drift`（偏离）、`noise`（噪声）。支撑性工作必须说明通往后续实验、论证、图或决策的具体联系。缺少已检查证据属于不确定性，不能据此把活动判为噪声或偏离。

追问知识、机制、证据边界、方法能力或决策究竟改变了什么。按任务已接受的标准判断深度，而不是数产出物或活动广度。只有任务明确确立博士标准时，才应用这一标准。发生偏离时提出纠正建议，不擅自修改已接受的研究方向。

**学习。** 当复盘需要生成回忆或预习提示，或更新已授权的学习存储时，阅读[伴学](references/companion-learning.zh.md)。分清来源有效性与已展示的理解。只读复盘可以提出知识项和检查问题，但不创建台账、不更新掌握状态，也不设置提醒。

**无人值守交付。** 准备自包含的未来运行提示，或审查已有任务的交付链时，阅读[无人值守复盘](references/headless-automation.zh.md)。准备提示词与安装、修改定时任务是不同动作。

### 4. 完成四部分复盘

**反思。** 将结果与基准比较，识别最重要的改进、偏差、失败或教训，解释其对目标的影响。区分有证据支持的原因与假设，选择哪些应继续、改变、停止或等待决定。

**总结。** 先说实质变化：状态变化 → 证据 → 影响 → 剩余不确定性。纳入会影响决策的未完成工作。统计文件、笔记、提交或会议数量不能替代实际结果，除非数量本身就是已接受的交付要求。

**推进。** 选择决策价值高、前提已满足、结果可观察的一项行动。只有只读权限时，指出下一步需要的确切输入、文件、检查、依赖或决策。获准执行时，仅执行已约定的有界动作并验证效果。获准维护台账时，写后检查预期状态变化。分清建议、尝试、已执行、已验证；副作用不明时先检查，不能盲目重放。

**规划。** 保留已接受的结果覆盖范围，延续有价值的工作，并解释拟延期的事项。使用项目现有状态，或以下默认映射：

| 状态 | 必需内容 |
|---|---|
| `[plan]` | 触发条件、具体行动、产出物与验收检查 |
| `[doing]` | 已实际开始的动作、当前节点与下一次检查 |
| `[blocked]` | 缺失前提、最小解除条件与复查触发点 |
| `[done]` | 已完成结果与已检查的验收证据 |
| `[drop]` | 已接受的移除、理由与重新开启条件 |

建议的下一步尚未开始时，不标为 `[doing]`。对必需范围提出的删减，在获接受前仍是待决策事项。默认每条工作流保持一项进行中任务，整个项目组合保持两到三项；用户明确指定其他在制品上限时遵从。每个保留项都需要可观察的下一步。日期和负责人只有在已知、已约定或明确标为建议时才写入。

## 要求

- [B] R1 明确范围与比较基准，包括区间/时区或其局限，以及基准或基准缺失。验证：将复盘开头的契约与已接受请求及已检查来源核对。
- [B] R2 重要进展和因果主张有可追溯证据或不确定性标注，观察、解释、决策、行动保持分离。验证：逐项检查结论与来源及相关结果。
- [B] R3 动作、状态写入和证据收集不超出实际授权，个人配置提供数据而不新增权限。验证：列出已执行动作和真实目标，检查效果，区分建议与执行。
- [B] R4 四部分复盘形成具体下一步计划，不虚构完成，也不悄悄删除必需覆盖范围。验证：检查每个保留任务的状态、下一步、验收或解除条件。
- [B] R5 研究、学习、无人值守模式遵守各自条件性的证据边界。验证：适用时检查主线锚点与判断、学习来源/掌握区分或交付链证据；否则以范围理由记为 n/a。
- [B] R6 所有已接受结果及适用阻断要求都有最终台账状态和证据或理由。验证：回读写入的产出物，将台账与真实已完成、未完成工作核对。
- [A] R7 优先级和进行中工作适合现实的下一阶段。验证：指出最高价值下一步、明确取舍和在制品上限。

## 何时停止

复盘和计划已经形成，且所有适用阻断要求均有证据标为 `done` 时停止。仅规划任务完成的是复盘与计划，未来行动仍未执行。

缺少授权、必需输入或关键前提时，停止受影响动作，继续独立且已授权的复盘工作。用完约定证据预算并完成最终检查后，汇报已完成事项、未解决缺口和最小解除条件。未满足的必需结果保持 `blocked`，预算耗尽不等于任务完成。

不从本次复盘创建循环自改进流程或调度器。潜在改进可以作为建议计划项；后续实施另受授权和证据约束。

## 输出契约

在对话或已授权目标中交付一份复盘，包含：

1. 范围、区间/时区、比较基准、已检查来源和重要覆盖局限。
2. 有证据、决策和不确定性的反思及实质总结。
3. 推进动作的真实状态、验证情况及实际修改的目标。
4. 状态真实、检查具体、依赖明确的下一步计划，以及适用的研究主线判断或学习复习/预习提示。
5. 验收台账（`事项 | done/blocked/n/a | 证据或理由`）、停止条件和剩余解除需求。

标题与篇幅可按受众调整，但必须保留验证结论所需的信息。用户请求无人值守提示词时，提示词就是产出物；明确说明是否真的配置或运行过任务。
