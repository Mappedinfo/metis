# research-diagram

[唯一发现入口](SKILL.md)。本文件为中文自有主稿，入口为同步英文译文。两份共享
方法、边界、验收与预算；发现文件名不赋予语言语义优先权。来源与变化见
[PROVENANCE.md](PROVENANCE.md)。

## 何时使用

适用于箭头和阶段承载含义的方法流程、机制、概念框架或项目路线图。数值图用
`scientific-plot` 或 `table-chart`。科学主张需由所给材料支持，画箭头不能证明因果。
制作默认交 Mermaid 源码和 SVG；建议／审查可以交具体方案或发现，制作请求必须有
实际可编辑源码和渲染文件，不能只告诉用户怎么画。

## 方法

1. 确定角色、读者和载体：过程顺序、机制、概念关系或里程碑。抽出主信息与所给
   证据，区分操作、材料、测量、假说和已接受结果。机制中的推断关系明确标记，
   路线图区分计划和已完成阶段。复用所给术语，保留请求的图件数量。
2. 先建节点与边的含义映射，再布局。关键节点说明对象或操作，适用时写清输入、
   输出和验证。每条边有类型：顺序、数据传递、依赖、反馈、相关或有支持的因果。
   记录其证据或逻辑依据，不能把相邻框自动变因果链。数量未知保持未知，只有演示
   请求才允许自造教学占位内容。
3. 按读者任务安排阅读路径。只有依赖保留时才把实现细节合并为有意义阶段；分支、
   反馈和人工修正分别标明。所给样本有帮助时展示一个具体输入或输出，不只写
   “数据／模型／结果”。符号定义和详细论证留图注或正文，不把所有字缩小塞入图中。
4. 读取选定的项目 `profiles/<name>.yaml`：稿件图用 journal，幻灯片图用 deck，
   或采用项目既有变体。配色、字体、尺寸和图注位置为可被用户／投稿要求覆盖的
   默认值，不决定研究方法。保存 profile 和覆盖记录；缺 profile 是准备条件，
   不能借用个人样式或学校素材。
5. 制作源码并实际渲染。Mermaid 保存 `.mmd`，按 profile 配置文字和样式，用可用
   渲染器导出 SVG；制作时读 [production.zh.md](references/production.zh.md)。
   要求 draw.io 时使用原生文字、形状和连接器，重新打开检查编辑保留。插图可作
   辅助，科学标签和关系保持可编辑；生图工具可选，不是制作真实方法图的前提。
6. 按使用尺寸查看实际文件。逐条箭头对照含义映射，检查阅读顺序、可读性、裁切、
   重叠、字形、图例及依赖颜色的区分，核对 profile 的图注位置。要求编辑能力时，
   在测试副本改一个标签或连接器并重新打开。SVG 是可检查的矢量输出，不等于
   保留源码级图形语义。

为接受的任务和下方 R1–R6 维护同一份验收台账，逐项记录 `done`、`blocked` 或
`n/a`，附实际产物的位置或范围理由。不能用 `n/a` 免除用户要求；方案不能证明执行。

## 验收要求

- [B] R1 角色与科学边界明确：对照所给材料检查节点和主张，计划与推断关系明确标记。
- [B] R2 关系含义正确：逐条关键边对应类型、证据和节点映射中的依赖。
- [B] R3 风格与标签匹配载体：检查实际 profile、覆盖要求、字形、图例与图注位置。
- [B] R4 要求的制作产物存在：打开可编辑源码和实际渲染；仅建议可 n/a，制作不能免除缺失渲染。
- [B] R5 实际文件经过视觉检查：按使用尺寸查看，记录可读性、交叉、裁切、符号及关系核对。
- [A] R6 代表性编辑可保留：要求原生编辑时在测试副本操作，否则说明源码可编辑为何足够。

## 何时停止

一次逻辑和布局检查，一次导出与视觉检查，最多一轮限定修复及受影响产物复查。
渲染器启动失败最多一次配置重试。所求制作／建议和必需项通过后交付。渲染或必要
编辑核验仍不可用时把已有源码交为部分结果，缺失项保持 blocked，说明最小渲染器、
字体或访问条件。

## 交付契约

交付要求的源码和实际导出、精简的节点／边含义映射、profile 和覆盖记录、渲染环境
与视觉检查，以及验收台账。默认 Mermaid 配 SVG，要求 draw.io 或支持的其他格式
时保留要求。不把可编辑图换成一张整画布图片。来源与改写见 [PROVENANCE.md](PROVENANCE.md)。
