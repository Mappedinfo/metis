# 数据准备

把有明确观测单位和列含义的原始表转换成可分析的数据，保留原件，并说明每次转换。

## 何时使用

清理 CSV、核对类型、缺失值、主键、单位或合并规则时使用。准备好的表格出图交给
`table-chart`；描述诊断交给 `exploratory-analysis`。模型分数提高不能单独支持补值
或删样本；准备请求也不自动授权重新获取、上传数据或覆盖原件。

## 方法

1. 明确一行代表什么、总体与时间范围、主键、测量单位和下游用途。数字形式的 ID
   保持标识符身份；同一对象的不同时间观测应按正确的复合键判断重复。
2. 清点文件、行数、缺失记号、无法转换的值、重复键和单位冲突。区分空白、零、未测量
   和结构性缺失；含义不明确时暂停依赖它的转换，继续独立可做的检查。
3. 将类型、缺失、排除、重复、连接、时区、单位和派生列规则写明，保留原始列或来源映射。
   合并先确定一对一／一对多等关系，记录未匹配行；多对多扩张须符合预定观测单位。
4. 将规则应用到新输出。需要从数据学习的补值、编码和缩放仅拟合获准的训练分区，保留
   分区与拟合范围。展示调整不重新拟合预处理。
5. 核对输入输出数量、主键、缺失、范围、连接扩张和单位。按源记录记下删除、填值及其规则；
   聚合结果抽查贡献记录，不用“程序成功”代替数值核对。
6. 交付数据字典、规则、记录审计与源哈希，维护要求台账；语义决定未解决时明确其影响。

结构与列含义已确认的表格，默认用成熟库整表计算（Pandas/Polars/DuckDB；空间数据用
GeoPandas），列运算优先于逐行循环。分块、流式或逐条处理只在内存不够、格式特殊或确需
记录级留痕时使用，那是内存与审计决策，不是默认的保守姿态。

仅当请求落在其支持范围内、或确实需要无依赖环境与逐条审计留痕时才读
[CSV 辅助程序合同](references/csv-helper.md)。它支持显式类型、缺失和重复操作，不
代替一般连接、复杂格式或分析设计；常规清洗不要把它当成默认路径。其他操作使用当前
可用的成熟库，保留相同审计要求。[虚构案例](examples/cases.md)可用于边界验收。

## 验收要求

- [B] R1 明确观测单位、键、列含义和规则；未确定的规则未应用。
- [B] R2 原件哈希不变，删除、填值、连接可追溯，输入输出数量与来源映射一致。
- [B] R3 查看实际数据，核对类型、单位、键和分区规则；需要时验证拟合范围。
- [B] R4 所有用户要求在台账中标为 done／blocked／n/a 并附证据或范围理由。

## 停止与交付

一次清点与应用、最多一次修复、一次最终检查。交付新表、字典、转换规格、源哈希、
数量核对、记录审计及台账。未知含义或连接规则使相关转换保持 blocked；预算耗尽时
报告可用诊断、未完成项和最小缺失决定。准备完成不证明科研结果成立。
