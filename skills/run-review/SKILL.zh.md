# 运行审查

核对运行原件能证明什么，分别判断完整性、可复现性、指标与科学解释。

## 范围与方法

用于已运行实验、复现结果或所给报告；不执行实验，不改原始记录，不给自动科学正确性分数。
没有 manifest 时按现有原件审查并明确缺失来源。正文论证审查交给 `manuscript-review`。

1. 明确接受的问题、协议、声称结果和获准证据范围，区分 smoke、评价与复现。
2. 查看终止状态、实际退出码、命令、输入、环境、必需输出、日志、日期和哈希。比较原件，
   不单独相信顶层成功标签；逐项记缺少什么。
3. 核对指标定义、单位、样本／分区分母、聚合、对照、种子、不确定性、泄漏、调参范围及
   协议偏差。有输入时重算关键数字；仅为审计不自动启动高成本重跑。
4. 将每个科学主张对应到已检查原件或来源。论文目标须实际核验；区分反证与未提供证据，
   保留限制与未解释差异。
5. 分开给执行／完整性与科学判断。重要原件缺失或矛盾为 required_fix；证据完整但执行失败
   为 rerun；可用但有限制为 accept_with_limits；适用的主张检查实际通过才为 accept。
   模型判断不能抹去完整性失败。
6. 审查写在原件之外，台账注明每个要求的证据与状态，给出最小修复或补证条件。

通用完整性与主张审查由本技能负责。项目或宿主为当前 manifest 或独立报告指定适配器时，
读取该适配器，以其支持的字段和既有输出格式检查，再用上述方法审查同一证据。适配器的
完整性结论与科学判断分开；不默认重复运行两套完整性检查，也不将不同清单格式视为等价。
公共技能不依赖私人适配器。

`scripts/review.py` 支持 `experiment-run` 的本地 v1 manifest，命令见英文入口。
它只检查原件完整性，保留 `scientific_status=unverified`。其他格式按实际字段写适配，
不需要私人 Harness；旧状态标签不能直接当作同义判断。

## 验收与停止

- [B] R1 审查前后原件哈希不变。
- [B] R2 完整性与科学检查分开，主张对应到协议、指标与所查来源。
- [B] R3 缺失、矛盾、限制与结论一致，未经核验的主张未被升级。
- [B] R4 完整交付所请求审查，要求逐项 done／blocked／n/a 并附依据。

一次证据检查、最多一次针对性澄清／审查修复、一次核对。审查报告可以完成并指出运行
失败；无法核验的科学主张保留未验证状态。预算耗尽时报告可用结论、未完成项与最小补证。
交付证据位置、两类判断、限制、修复优先级和台账，自动完整性程序不能单独完成科学审查。
