# 多来源幻灯片

将充分的材料转成受众能理解、检查或据此判断的演示，交付实际可编辑文件。

## 范围

用于多来源、进展、教学与自定义报告。单篇论文、中文、10–15 页的固定组会请求使用
`taskbook-slides`；多篇证据尚未完成分析时先用 `literature-synthesis`。呈现阶段不扩大
检索，也不为填满页数补造结论。

## 方法

1. 明确受众、目的、时长或页数、语言、材料覆盖和输出格式。接受精确页数；未指定时
   选择能覆盖证据和讲述的最小规模。编辑既有文件时保留模板、尺寸、前言和源码配置。
2. 将关键主张、数字和图片对应到材料位置，区分已观察进展、解释、拟议行动和未知项。
   来源只支持事实说明时，不强加建议或创新结论。
3. 逐页安排问题、信息、证据和讲述作用：陌生概念先解释，结论有证据，保留必要例子。
   只有共同行列属性确实有比较价值时才用表格。
4. 读取项目 `profiles/deck.yaml`，应用颜色、字体角色、尺寸、最小字号与导出要求。
   嵌入图仍保留自己的 profile；既有命名变体不覆盖。标题、标签和来源在放映尺度可读。
5. 用当前可用工具生成可编辑 PPTX，或请求的 Beamer 源码和 PDF。尽可能保留文字、表格、
   图解可编辑，保留数据和图片来源。每页备注写解释、过渡、来源和不确定性提示，不仅复述。
   格式制作与最终文件检查见[后端指南](references/backends.md)。
6. 渲染实际交付文件，逐页全尺寸检查截断、遮挡、换行、连线、对比度和图表忠实性。
   备注单独检查。局部修复复查相关页；母版、字体或全局布局变化复查全套。
7. 对照完整材料、请求和来源映射验收。无法渲染时可以交付有用源码，但视觉项保持 blocked。

## 验收与停止

- [B] R1 实际文件满足受众、语言、格式、页数和覆盖要求。
- [B] R2 关键数字、结论和素材逐项可定位到所给来源。
- [B] R3 实際应用 profile；检查尺寸、颜色和字体角色，保留既有模板／变体。
- [B] R4 每页有可用备注，实际最终文件逐页渲染和查看；源码属性不能代替视觉验收。
- [B] R5 可编辑源码、所请求导出及台账齐全，全部要求有证据或明确未完成状态。

一次材料／规划／制作、最多一次限定修复、一次最终内容与视觉核对。预算耗尽说明已交付
文件、未完成检查和最小缺失来源、渲染能力或决定。默认 PPTX；请求 Beamer 时交付 `.tex`
与编译 PDF，附备注、来源映射、再生成资产和台账。生成成功不自动等于通过验收。
