# 后端与导出

核心能力是受众、证据、讲述和交付验收，不依赖某个私有编辑器。先选当前真实可用的
制作和渲染工具。使用平台演示技能时遵守它的工具合同，不将平台专用路径写进公共源码。

## PPTX

默认可编辑 PPTX。当前有可用演示工具就使用它；独立环境可采用公开的 PPTX 制作库，
如 PptxGenJS 或 python-pptx，并明确可用渲染器。导出后读取实际文件中的页数、文字、
备注和来源，再用当前工具渲染实际 PPTX；单独生成的 HTML／PNG 草稿不能冒充 PPTX 渲染。
可用渲染路径包括当前平台的演示导入／导出、LibreOffice 或已授权的本机演示应用。
未检测到渲染能力时说明视觉验收未完成，不盲目安装或打开交互应用。

通过 profile 的字体角色取具体字体；在当前平台核实字体，替代须记录。与数字有关的
图表保留数据与分母，检查导出包里的可编辑结构，而不是只凭屏幕像素判断可编辑性。

## Beamer

使用通用 Beamer，不附学校标志或不明许可模板。既有 `.tex` 保留前言、引用和编译方式；
新文档按请求语言选择合适编译器。根据 profile 明确 `aspectratio`、颜色和字体大小，
并保留 `\note{}` 或并列的逐页讲述记录。参考[Beamer 官方手册](https://tug.ctan.org/macros/latex/contrib/beamer/doc/beameruserguide.pdf)。

编译实际源文件，核对日志；生成 PDF 后实际渲染每页并查看。没有错误日志不证明布局
没有遮挡，`.tex` 存在不证明 PDF 已编译。字符、数学和中文字体须在目标编译路径中检查。
一次源码和 profile 保存可用于再生成，不复制私人格式宪法。
