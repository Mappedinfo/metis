# research-question

[唯一发现入口](SKILL.md)。本文件为中文自有主稿，入口为同步英文译文。两份共享
方法、边界、验收与预算；发现文件名不赋予语言语义优先权。来源与变化见
[PROVENANCE.md](PROVENANCE.md)。

## 何时使用

适用于问题、价值、可检验性或可行性尚未明确，以及比较候选研究问题。问题接受后
的执行拆解用 `research-taskbook`；已有结果支持明确问题、只需组织论证和图序时用
`research-story`。漂亮表达不能代替问题价值，表达不佳也不能单独成为淘汰理由。

## 方法

1. 判断起点是主题、空白主张、假说、方法想法还是决策问题，把当前问题写成一个
   未知及答案有作用的条件。按请求确定读者、现有证据、时间和资源，只问会改变
   候选集的缺失约束。领域词不是问题，新方法名字不是贡献。
2. 建立最小证据基础：检查所给权威来源，找到最近的已有答案或现实替代方案。
   当前领域事实影响选择时，用获准的学术检索核对。区分有来源的事实、推断与假设；
   有限检索没结果不证明没人做过。访问缺失使新颖性或可行性暂定，不自动判为失败。
3. 按当前张力提出或修复问题：隐含假设、竞争解释、失败边界、更简单的替代方案、
   条件变化后可测的旧限制，以及影响选择的系统性错误。需要比较时才用多个视角；
   修复一个问题不用生成长清单。
4. 对认真考虑的候选同时检查五件事：价值对象是谁或是什么、最接近的已有知识、
   答案可能改变什么、什么观察／证明／案例会削弱它，以及可用什么材料辨别。
   新定义、孤立构造例子和空白声明需说明后果才有意义。按方法选择证据标准：理论
   检查证明与反例，实验检查公平协议和不确定性，因果主张检查识别假设，解释研究
   检查材料与竞争解读。
5. 用最强竞争解释及最有后果的拒绝风险检验候选。设计最小但有信息量的试探：
   输入、比较或控制、可观测输出、判定规则，以及不同结果对应的行动。区分计划
   与已完成证据。阈值依照接受的尺度或变异估计；没有基础时判断保持暂定。理论
   或资料分析问题不强求实验。
6. 根据证据和资源建议推进、修复、暂放或放弃。未解证据应成为下一步核对，不能
   编成分数或失败证明。保留有价值的负面结果与适用范围。问题卡记录问题、价值、
   最近替代、预期增量、假设和竞争解释、证伪条件、可行核对、资源、拒绝风险与
   下个决定；窄请求简短作答，这些是检查字段，不是强制正文标题。

为接受的任务和下方 R1–R6 维护同一份验收台账，逐项记录 `done`、`blocked` 或
`n/a`，附实际产物的位置或范围理由。不能用 `n/a` 免除用户要求；方案不能证明执行。

## 验收要求

- [B] R1 区分问题与主题／方法／计划：核对未知、成立条件和答案类型。
- [B] R2 价值与增量有依据：比较最近已有答案或替代方案，未解价值和新颖性标明。
- [B] R3 证据与假设分开：关键来源有核对位置，缺失声明限定于实际检索范围。
- [B] R4 有意义的证伪条件及可行核对：不同竞争结果能改变建议，不补造证据。
- [B] R5 结论匹配资源和不确定性：对照所给约束检查建议、最强风险及下一行动。
- [A] R6 替代方案或有用负面结果支持选择：要求比较或会改变决定时展示取舍。

## 何时停止

一轮候选生成／修复，一批获准的关键缺口证据核对，再做一轮检验／修复。所求建议
和必需项通过后交付。预算耗尽仍缺支持时交暂定问题卡，说明最小缺失来源、资源
估计或人工决定；必要的新颖性／价值判断保持 blocked，不冒充成熟结论。

## 交付契约

交付所求问题卡或局部评价、相关来源和替代比较、有辨别性下一步的推进／修复／暂放／
放弃建议，以及验收台账。建议不授权研究状态写入、启动实验或实现下游工作。
