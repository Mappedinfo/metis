# table-chart

根据已准备 CSV 的语义类型及读者需要的比较，推荐并绘制图表。
提供图形与排版备选方案、共享的无障碍导向或 NPG 风格样式配置，以及可复现的导出物。
数据清洗和统计推断不在本 skill 的范围内。

## 何时使用

用户已有准备好的 UTF-8 CSV，需要帮助选择图形或完成绘制时使用。
支持水平条形图、点图、折线图、散点图、直方图、箱线图和热力图，
并在相应图形支持时采用分组或分面排版。依据读者的问题和列的含义选择：
看起来是数字的 ID 属于类别，数值年份则可能表示时间。
规划器的建议是候选方案，不是对语义的最终判定。

选择图形、编写绘图规格或选择配色时，阅读[图形与排版指南](references/chart-guide.zh.md)。
原始数据清洗、缺失值填补、单位推断、统计检验、拟合模型、地图和不确定性估计
需要单独的数据准备或分析任务。直方图和箱线图提供参数有记录的描述性汇总；
它们不证明显著性或因果效应。

## 方法

1. 根据请求和数据说明确定比较问题、所选列、语义类型、单位及符合事实的标题。
   需要解释时添加图注，仅使用已提供的量、单位、汇总口径和来源。保留输入数据。
   尚未选定方案时，运行规划器并比较备选方案：

   ```sh
   uv run --with 'matplotlib>=3.7,<4' --with 'PyYAML>=6,<7' python \
     /path/to/table-chart/scripts/chart.py plan \
     --input /path/to/prepared.csv --output /path/to/new-plan.json \
     --types '{"sample_id":"categorical","date":"temporal"}'
   ```

   仅在请求初步评估时省略 `--types`。说明选定图形为何适合该问题、一个有用的备选图形，
   以及拟采用的单图或分面排版。补齐选定规格中的标题和必需单位，不能仅凭列名推断。
   如果只请求方案，交付方案并说明尚未绘制。
2. 阅读目标项目中选定的共享 profile：`journal` 使用基于 Okabe–Ito 的分类颜色，
   `journal-grayscale` 用于单色，`journal-npg` 使用 ggsci 的 NPG 风格色系。
   后者不是 Nature 官方样式，也不保证色盲或灰度可辨识性。
   除颜色外，同时检查冗余编码：点形、线型、填充纹理或分面。
   `uses` 目标在 `<project-root>/profiles/` 下解析；缺失时按照 metis-os 的
   [profile 安装指南](https://github.com/mappedinfo/metis/blob/main/profiles/README.md)安装。
   颜色值、字体和导出默认值归 profile 管理；本地变体使用新的 profile 名称。
   集合的排版标准要求整图标题及图注位于整图下方，每个子图的标题位于对应面板下方。
   profile 将 `figure.title_position`、`figure.caption_position` 和
   `figure.panel_title_position` 声明为 `below`。坐标轴标签仍靠近对应坐标轴。
3. 使用明确路径绘制已确定的规格：

   ```sh
   uv run --with 'matplotlib>=3.7,<4' --with 'PyYAML>=6,<7' python \
     /path/to/table-chart/scripts/chart.py render \
     --input /path/to/prepared.csv --spec /path/to/chart.spec.json \
     --profile /path/to/project/profiles/journal.yaml \
     --output /path/to/new-chart-output
   ```

   需要 Python 3.10+、Matplotlib 和 PyYAML。输出路径必须是新路径。
   渲染器拒绝所选值缺失或无效、非有限或无法表示的数值、超过 10,000 行的数据、
   单个分类轴超过 20 个类别、超过六个组或面板，以及热力图中的重复单元格。
   热力图要求完整网格。报告数据准备障碍，不能悄悄删行、平均重复观测或填补缺口。
   折线排序与直方图、箱线图汇总属于有记录的数据变换。
   原有[条形图绘制器](scripts/bar_chart.py)仍可用于原来的 category/value 接口。
4. 按最终使用尺寸检查导出物和灰度预览。核对映射、单位、顺序、尺度、图例、面板对齐、
   字形、裁切、标题和图注是否位于图下方，以及各组能否在没有色相差异时仍被辨认。
   单份预览不能证明所有视觉条件下的可访问性。
   字形不受支持时，需要在命名 profile 变体中指定已安装的字体；中文需匹配的 CJK 字体。
   查看实际最终 PDF 或栅格导出，不能只检查代码或渲染成功回执。
5. 按已接受的范围为生成的要求台账补充证据。渲染器会将视觉检查保留为待处理。
   最多进行两轮针对性修复，每轮使用新的输出目录，之后报告未解决的要求及最小解阻条件。

## 要求

- [B] R1 选型符合数据和问题——验证：方案或规格列明语义类型、单位、所选图形、排版及选择假设；
  绘制前解决含义歧义。
- [B] R2 数值与变换可追溯——验证：来源哈希、所选列、行映射及记录的排序、分箱或箱线统计
  能够解释图中数据；不存在隐藏的删除、填补或聚合。
- [B] R3 应用共享样式和排版——验证：回执记录确切 profile、尺寸、配色及编码选择、
  实际字体、标题和图注位置、导出设置，并与规格一致。
- [B] R4 最终图已进行视觉检查——验证：台账标识已查看的导出文件和灰度预览，
  记录映射、可读性、组间区分、字形及裁切检查，包括坐标轴标签、子图标题与整图图注是否分离。
  明确只要求方案时，该项为 `n/a`，同时说明尚未绘制。
- [B] R5 执行可复现——验证：绘制交付输入、规格、profile 和可执行脚本快照，
  软件版本记录以及复跑命令。仅交付方案时记录输入、候选项及未决信息，不声称已执行。
- [A] R6 说明配色限制——验证：推荐区分类别、顺序和发散用途；选用 NPG 风格配色时说明其来源。

## 何时停止

请求的方案或成图及其适用证据已交付时停止。绘图请求在图像尚未检查时仍未完成。
不增加无关图形，也不把描述性图表扩展为分析结论。

遇到缺失的语义决策、输入/profile/字体障碍、不支持的图形或修复预算耗尽时停止。
报告已完成项和受阻项。数据超出渲染器的可读性限制时，提出明确的数据选择方案或其他工作流；
不得自动截断类别或观测。

## 输出契约

方案任务交付列评估及排序后的候选图形，包含排版和样式选择、假设、备选项及待补字段。
绘制任务交付 profile 要求格式的图表、灰度预览、`input.csv`、`spec.json`、
`profile.yaml`、绘图脚本、`receipt.json` 和已填写的 `requirements.md`。
链接最终图，并报告实际视觉检查结果及仍存在的限制。

回执将输入、profile、脚本哈希以及映射和变换，与尺寸、字体、导出、软件版本和复跑命令关联。
来源快照和回执与用户的交付物共同保存；发布是区别于绘图的另一项行动。
