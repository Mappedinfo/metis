# 选择图形、排版与 profile

本指南帮助将读者的问题和已准备的数据列转化为可绘制的规格。
文件能被解析出的类型用于缩小选项范围；变量的实际含义决定哪些选项合适。

## 数据与比较问题

| 数据与问题 | 首选候选 | 有用的备选及排版 |
|---|---|---|
| 类别 + 一个值：比较大小 | 使用零基线的 `bar` | `dot` 可更紧凑地比较位置。除非已明确准备其他顺序，否则保留来源顺序。水平标签适合较长的类别名称。 |
| 类别 + 值：比较多个系列 | 分组 `bar` 或 `dot` | 标签或标记拥挤时按系列分面；使用共享尺度，避免面板大小暗示不同量级。 |
| 有序数值或时间 x + 值：展示沿序列的变化 | `line` | 当连接数值 x 上的观测会暗示没有依据的连续过程时，改用 `scatter`。当前散点渲染器要求数值坐标轴。多个系列同时采用点形、线型和颜色编码。 |
| 两个数值变量：展示关系 | `scatter` | 系列重叠时按分组列分面。视觉上的关联不等于拟合模型或因果估计。 |
| 一个数值变量：展示分布 | `histogram` | 选择并报告分箱数；比较各组时使用相同箱边界或对齐的分面。分箱会改变外观，不能揭示唯一的分布形状。 |
| 类别 + 重复数值观测：比较分布 | `box` | 按类别分面的直方图能更直接地显示形状。保留离群值，报告箱体/须线口径和各组样本量；箱体不是置信区间。 |
| 两个类别 + 每一对类别对应一个值：比较矩阵 | `heatmap` | 使用有序行列和带标签的色条；顺序色阶表示大小，发散色阶则需要用户提供有意义的中心值。重复或缺失单元格需要先处理。 |

数值 ID、邮政编码、处理组代码和年份是常见歧义情况。用 `--types` 覆盖规划器的评估；
不要把无关的数字标识符连成趋势线。重复类别可能表示适合箱线图的重复观测，
不能为了画条形图而暗中求均值。
时间列当前接受 ISO 日期（`YYYY-MM-DD`）。明确其顺序含义后，数值年份可作为折线图的数值 x；
将其声明为 `temporal` 不会把它转换成完整日期。

渲染器最多支持 10,000 行来源数据、每个分类轴 20 个类别、六个系列或分面。
这些是实现限制，不表示限制以内的每张图都可读。它不会对点抽样、合并类别、
填补缺失值或为条形图计算汇总估计。当可区分的编码不足时，profile 能同时支持的系列可能更少；
此时使用分面。规划之前，最多选择 60 个输入列。

## 排版决策

先用一个面板回答一个比较问题。较短的类别列表或单个系列适合单栏宽度。
矩阵、多个长标签或并排分面使用双栏宽度；尺寸和字号取自所选 profile。
缩小文字之前，先尝试加宽或拆分图形。

集合采用统一的标题与图注位置：整图标题及可选解释性图注放在整图下方，
各子图标题放在对应面板下方。坐标轴标签仍位于轴附近。
在轴标签下方预留独立空间，避免子图标题、刻度标签和整图图注重叠。
profile 的 `figure.title_position`、`figure.caption_position` 和
`figure.panel_title_position` 均为 `below`。

已有相关信息时，用图注说明量、单位、图中汇总统计量的含义及来源。
例如，箱线图图注可以解释回执中明确的中位数、四分位数和须线口径。
不要为了填满图注而编造来源、解释或结果。没有来源的虚构示例应明确标为虚构。

需要读取同一个 x 位置的差异时，可以叠加少量可区分系列。
如果重叠会遮蔽观测，或者图例给读者增加负担，优先采用分面。
两个面板通常可以排成两列；三到六个面板应按最终尺寸比较两列和三列方案。
同类坐标轴和颜色范围保持可比较，面板顺序保持稳定。
未使用的网格位置留空，不作为额外数据面板。
面板宽度至少为 50 mm。热力图任一轴超过八个类别时必须使用双栏宽度；
单元格标签必须放得下，不能悄悄舍入数值。

当前 `facet` 模式将 `group` 列拆成相同图形类型的多个面板，
不会把无关图表组合成论文中的复合图。每项不同的比较需单独提供规格。

## 配色选择

先依据颜色通道的含义，再依据输出媒介选择配色。
无序标签用分类颜色，有序数量用顺序色阶，只有存在明确且有意义的中心值时才用发散色阶。
实际颜色和样式以 profile 为准。

| Profile | 何时选用 | 检查内容 |
|---|---|---|
| `journal` | 默认的期刊式类别比较，采用基于 Okabe–Ito 的色系 | 颜色需结合点形、线型、填充纹理或分面。打印后，相近灰度仍可能重合。 |
| `journal-grayscale` | 单色或优先考虑打印的交付 | 按最终尺寸检查明度对比和非颜色编码；仅靠相邻灰色填充可能不足。 |
| `journal-npg` | 用户要求 ggsci NPG 风格的分类外观 | 不是 Nature 官方配色，也不构成通用无障碍承诺。保留冗余编码并检查灰度预览。 |

生成的 `chart-grayscale.png` 用于暴露完全依赖色相的区分。
它是审查辅助，不是色觉缺陷模拟或无障碍认证。检查实际图中的标记重叠、对比度、
图例对应关系和灰度可读性。profile 的来源与配色定义在集合的
[profiles 指南](https://github.com/mappedinfo/metis/blob/main/profiles/README.md)中维护。

## 绘图规格

创建包含以下字段的 JSON 对象；下方示例均使用虚构数据。

| 字段 | 值 |
|---|---|
| `chart` | `bar`、`dot`、`line`、`scatter`、`histogram`、`box` 或 `heatmap` |
| `x` | 列名；bar/dot/box 使用类别，line 使用数值或时间，scatter/histogram 使用数值，heatmap 使用类别 |
| `y` | 列名；除 heatmap 的类别轴外均为数值；histogram 省略此字段 |
| `value` | 仅用于 heatmap 的数值列 |
| `group` | 可选的类别系列/分面列；heatmap 使用一个完整矩阵，不带分组列 |
| `types` | 将所选列名映射为 `categorical`、`numeric` 或 `temporal` |
| `units` | 将所选数值/时间列映射到明确单位；日期使用 `date`，无量纲数据也明确填写单位 |
| `title` | 任务提供的、符合事实且非空的标题；显示在图下方 |
| `caption` | 整图标题下方的可选解释文字；仅使用已提供的量、单位、汇总口径和来源信息 |
| `layout` | `{ "mode": "single" 或 "facet", "width": "single" 或 "double", "columns": 1、2 或 3 }` |
| `bins` | 直方图的分箱数，为 1 到 100 的整数；默认 10 |
| `center` | 发散热力图的可选数值中心 |

规划结果包含尚未填全的规格模板。绘制前，依据任务上下文补齐为 null 的标题和单位。
渲染器会再次验证这些选择；候选方案不等于已经完成的图形。

[观测 CSV](../examples/observations.csv)可与[折线规格](../examples/line.spec.json)配合使用。
该数据也可用于按 `series` 分组的 `temperature` 与 `score` 散点图、`score` 直方图，
或 `x: series`、`y: score` 的箱线图。对应规格使用 `degrees C` 和 `points` 作为单位，
并选择匹配事实的标题。每个系列内的折线点按所选 x 排序，回执记录该顺序。
直方图记录箱边界和计数，箱线图记录其描述性统计量。

[矩阵 CSV](../examples/matrix.csv)与[热力图规格](../examples/heatmap.spec.json)
用虚构的带符号差值演示明确的零中心。普通大小图省略 `center`。
[原始 CSV](../examples/example.csv)仍适用于 `bar_chart.py` 的 category/value 接口。

要生成分面折线示例，将折线规格的 layout 改为：

```json
{ "mode": "facet", "width": "double", "columns": 3 }
```

采用该排版之前检查最终面板。同一规格可使用任何兼容的 journal profile，
不需要把配色复制进规格。

## 维护者示例

使用新输出目录复现范围有限的虚构验收样例集：

```sh
uv run --with 'matplotlib>=3.7,<4' --with 'PyYAML>=6,<7' python -B \
  /path/to/table-chart/scripts/render_examples.py \
  --profiles /path/to/project/profiles --output /path/to/new-examples
```

这会生成覆盖全部七类图形的九个示例，包括分面折线图、NPG 风格散点图及灰度 profile 热力图。
索引和各图回执说明实际执行了什么；在检查真实导出物和预览之前，视觉检查仍为待处理。
这些虚构示例用于检验接口，不证明对所有数据都有效。
