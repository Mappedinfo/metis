# 来源简报

根据用户提供的材料起草或修改短简报，并为关键事实主张建立来源映射。
适用于“把这些笔记整理给团队看”“写一份简短进展”或“修改这份简报”等中文或英文请求。
不负责检索来源、选择研究方向或撰写完整学术论文。

将已有笔记、摘录或草稿整理成特定读者可以使用的简报。选择并解释相关材料，
不确立超出这些来源的事实。不需要私有服务或专用写作工具。

## 何时使用 / 不使用

材料已经具备，且交付物是简短进展、解释、摘要或改稿时使用。
遵循用户要求的语言、读者、目的、长度和格式。常规选择可依据上下文确定；
只有尚未解决的选择会实质改变内容时才提问。

如果需要先检索、开展原创分析或完成整篇论文，指出这项依赖。
有用时仍可先写有来源支持的部分，并明确缺失的证据。
用户提供文本不等于授权浏览、发布或发送简报。

## 方法

1. **明确简报的用途。** 确定读者需要理解或决定什么，在验收台账中记录已接受的约束。
   阅读相关材料，为每个来源分配稳定标识及可定位的位置：文件名加标题、页码、段落或行号。
2. **选择证据。** 区分已报告的观察、作者意见、拟开展的工作和缺失信息。
   对影响解释的数字、单位、分母、日期和不确定性予以保留。
   区分失败、受阻和未执行的工作。来源冲突时，描述分歧或采用用户指定的权威来源；
   日期较新本身不能解决事实冲突。
3. **写出一稿。** 从读者最需要的信息开始，用最相关的证据支撑。
   当局限会改变读者判断时纳入正文。用平实语言连接句子；仅在更便于使用信息时采用列表或表格。
   修改已有稿件时，保留有依据的含义和用户要求的语气。
   实质修改另行记录，不混入面向读者的简报正文。
4. **进行一次证据和适配检查。** 在 `source-map.md` 中，将每项关键可核查主张映射到来源位置。
   不要求每句话都有引文，但读者必须能够找到重要主张的证据。
   标明意见归属和拟议行动，删除无依据的主张或限定其表述。
   核对语言、读者、长度和格式要求。存在明确长度限制时，在台账记录计数口径及实测结果。
5. **只修复已识别的问题。** 最多进行两轮修复，每轮之后检查受影响的主张和约束。
   依据实际结果更新台账，不因文件已存在就宣称成功。阻断性检查通过后，不再继续润色。

输入不完整时，只写有依据的部分，并在来源映射中列出缺失材料。
如果某项必需结果依赖这些材料，将简报标为部分完成，并保留对应要求的 `blocked` 状态。
不得用看似合理的姓名、数字、比较或研究结论填补空白。

## 要求

- [B] R1 简报符合已接受的目的、读者、语言、长度和格式要求——验证：将交付文本与记录的约束逐项比较。
- [B] R2 关键可核查主张由用户提供的来源支持，重要数字、日期和不确定性得到保留——验证：
  逐项打开来源映射中的位置，与简报中的对应主张比较。
- [B] R3 意见、提案、冲突和缺失证据保留原有状态——验证：检查简报中使用的每项此类内容；
  缺乏依据但属于必需的内容标为 `blocked`，不得编造。
- [B] R4 每项已接受的任务要求及 R1–R5 都有状态和证据或理由——验证：阅读验收台账；
  `done` 必须有通过检查的依据，`n/a` 仅适用于已接受范围之外的要求。
- [A] R5 改稿披露实质修改——验证：来源映射列出主张、删略或重点的变化；新写简报时标为 `n/a`。

## 何时停止

- 简报和来源映射已生成，且所有适用的阻断性要求都已通过后交付。在台账中记录停止条件。
- 初稿和首次检查之后，最多进行两轮修复。如果必需检查仍不通过，交付可用的部分结果，
  并说明已完成项、未完成项和解除阻碍所需的最小输入或能力。预算耗尽不使受阻要求变为完成。
- 完全没有可用来源材料时，以缺失输入记录结束；不得编造简报或宣称完成。

## 输出契约

1. `brief.md`，或用户要求的文件名和格式。面向读者的正文不包含起草笔记和验收过程；
   保留理解实际主题所需的局限。
2. `source-map.md`，包含简洁的主张与来源位置对照表、重要缺口或冲突，以及适用时的实质改稿记录。
3. `source-map.md` 中的验收台账：要求 ID、`done` / `blocked` / `n/a`，以及证据或理由。
   包含停止条件和剩余工作。用一张小表即可，不需要额外的跟踪系统。

两者均为虚构材料。
