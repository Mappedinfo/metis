# 表达审校

## 能做什么

通读用户提供的文本，找出妨碍其写作目的的表达，并解释或实施最小的有效修改。
候选词句只是检查语境的线索，本身不等于问题。本审校不依赖脚本、网络、私有服务或其他技能。
适用于“检查 AI slop”“去 AI 腔”“检查黑话”等中文、英文或混合文本请求。

这是编辑审校，没有经过校准的作者来源模型，不得判定文本由 AI 或人类撰写，也不得给出两者的概率。
遇到“这是不是 AI 写的”，简短说明这一限制，再提供有依据的具体表达评价。

## 何时使用 / 不使用

用户明确要求检查或修改机械、空泛、夸张、结构过度或黑话密集的文字时使用；
也可作为已获授权的写作任务中与目标相关的最后一轮检查。
不要给每个无关回复强加这一步，也不要仅因引文包含词表中的表达就改写它。

本技能不鉴定作者、不检测抄袭、不核查外部事实，也不认证法律或科学正确性。
不以绕过检测器为优化目标：提升清晰度和准确性，不添加错误、人为不规则或虚构个人经历。

## 方法

### 1. 明确请求与阅读范围

从请求和现有上下文确定读者、体裁、目的、语言、受保护材料，以及已接受的长度和格式。
只有缺失选择会实质影响审校时才询问。采用以下模式：

| 模式 | 操作 |
|---|---|
| `audit` | “检查”“检测”或作者来源问题的默认模式：检查并报告，不改写整篇文档。 |
| `edit` | 用户要求修改时：报告重要问题，并交付完整的最小改动版文本。 |
| `result-only` | 用户说“只给改稿”时：执行相同检查，只返回所需正文；检查记录留在正文之外。 |

未获文件修改授权时，在对话中工作。保留原文以供比较。使用稳定位置：文件名加行号或段号；
粘贴文本使用段号、句子编号。排版使分段有歧义时，说明段落如何计数。

为已接受的用户成果及 R1–R8 维护工作验收台账：
`ID | level | requirement | verification | status | evidence or reason`。
结束时，每项状态为 `done`、`blocked` 或 `n/a`；`n/a` 必须有范围依据，不能用于免除必需成果。
任务未要求时，不必另建文件。

从任务中一次选定文体：科研论文正文和学术综述用 `academic`；科普、教学、口头解释与口播稿用
`explain`；其他或未指定的正文用 `general`。文体与语言、输出模式分别确定。
混合文档可按既有章节分别检查，保留位置与覆盖范围。
执行指令、审校记录与面向读者的正文分别存放；正文只包含用户要求的文字。

### 2. 先通读全部可用文本，再评价信号

阅读论点、事实、指代、顺序、语体和作者声音，明确每段新增了什么。
标记需要保留原形或重要区分的引文、引用、代码、标识符、法律条款和技术定义。
即使可选扫描器跳过这些区域，语义阅读仍应覆盖它们。

长文本先在已提供的范围内划分有限数量的块，依次阅读，用简短论证图记录跨块关系，
识别重复主张和断裂指代。记录每个已读范围。输入被截断或阅读预算耗尽时，
准确报告已覆盖与待阅读范围；不得把片段审校称为全文审校，也不得默默缩短交付物。

默认预算：一次完整语义阅读、最多一轮修改，以及一次针对受影响段落及其上下文的验证。
有限的分块清单属于第一轮阅读，不是反复重读的许可。采用其他预算前，先从任务中明确该预算。

### 3. 找候选，再依据语境判断

检查用词、句间逻辑、衔接、强调、重复和全文结构。
需要候选判断规则或误报检查时，阅读[信号判断指南](references/signal-guide.zh.md)。
其中的类别是阅读提示，不是穷尽的禁词表。

完成语义阅读后，本地 Python 和适合扫描的文本文件可用时，运行[本地扫描器](references/scanner.zh.md)，
通过 `--genre` 指定已选文体。程序固定加载 `scripts/rules.json`；每篇草稿不再生成禁词表、
检索历史对话或重列 SOP。按返回位置及邻近上下文处理候选，合并重叠命中，保持一次通读的预算。
运行时或文本文件不可用时，只读一遍既有规则，完成一轮有界人工检查，并记录该退路。
不要仅为启用检查而安装运行时或上传正文；仍支持人工审校。
档位和计数只决定候选展示，不决定编辑严重程度或作者来源置信度；零候选不证明文字质量。

文体对应的 `policy_action` 决定候选处理顺序。`academic` 将修辞性否定转折和连续否定标为
`revise`：直接陈述有依据的对象、方法或结果，例如“本研究记录降雨概率。”
`explain` 与 `general` 标为 `context`：帮助纠正常见误解时可保留，例如“记录的不是降雨量，而是降雨概率。”
真实的方法比较或必要排除仍须写成明确的事实关系。
“不冒充全局”“真实口径”等内部提醒始终需要语境判断：正文中用已有覆盖范围、证据或动作替代自我提醒，
或删除空泛铺垫。任务讨论执行过程本身时，这些表达可能相关。
不得补造具体细节，也不得机械删除引文、规则示例或真实限制。

对每项有实质影响的候选：

1. 摘录原文的精确片段并标明位置，检查邻近句子及该段作用。
2. 判断 `revise`、`keep` 或 `unresolved`。指出真实问题，例如行动者缺失、主张重复、
   无依据的强调，或衔接语宣称了文本未建立的关系。“词表里有”不是修改理由。
3. 对 `revise` 说明读者受到的影响，并给出最小修法。
   对重要的 `keep` 判断记录其作用，例如必要术语或有意义的对比。
   对 `unresolved` 指明缺失的证据或意图，不猜测补齐。
4. 同一问题触发多个规则时合并。重复问题集中列出位置，不把每次关键词命中算成独立缺陷。

按影响分级：`high` 改变主张、责任、确定程度或决策；`medium` 遮蔽论证或造成大量重复；
`low` 是局部干扰或冗词。同一句触发多个模式不会自动升级。
同义循环和假范围必须从含义上解释，正则表达式不能证明它们存在。

### 4. 仅在要求修改时改稿

保留原意、证据、数字、单位、日期、比较、引文引用、真实不确定性及有用的作者语气。
保留必要的 AI 术语、真实的 API 或法律契约、科学限定、有意义的否定、合理的被动语态，
以及具有实际分类作用的三项列表。不要一律换成口语。

优先删除重复铺垫、点明原文已知的行动者，或直接表达有依据的关系。
缺少具体细节时，指出缺口或保留准确的概括；不得虚构指标、因果机制、事件、引语或个人经历。
不得把“可能”改成确定结论，也不得因为限制说明听起来程式化就将其删去。
未经明确许可，不改动引用的来源原文；将编辑说明放在引文之外。

在含义层面修复修辞模式。换同义词或把破折号换成逗号，不能修复空洞对比。
只在有助阅读时改变句长或段长，不追求所谓人类写作分布。
口语、错别字、情绪、时间或地点细节均不能证明真实，也不能证明人类作者身份。

交付已接受范围内的完整改稿，保留未改动部分。替换建议清单不能代替全文改稿。
输出放不下时，使用已获授权的文件或已约定的分批方式；否则说明必需的全文交付仍受阻。

### 5. 验证并结束

将改稿与原文比较，检查主张变化、丢失的限定、数字、归属、引文及断裂指代。
在段落语境中检查受影响的文字，并检查用户要求的全部范围是否保留。
`audit` 模式则核对摘录、位置、理由和修法。可选择复跑扫描器，但它不能替代这一步；
零命中不是验收目标。

根据实际发现给出表达总评，例如“已检查范围内未发现实质表达问题”“局部修改有帮助”，
或“反复出现的表达问题妨碍论证”。避免“高度疑似 AI”“人类分数”等标签。
记录停止条件、覆盖范围、未解决项及台账依据。

## 要求

- [B] R1 模式、目的、范围和实际阅读覆盖与请求一致。验证：将已接受约束及已读范围与交付的审校或全文改稿比较；披露缺失或截断文本。
- [B] R2 发现建立在语义通读之上，包含原文精确片段、位置、语境理由、影响等级和最小修法，并合并重叠缺陷。验证：逐项回看所报段落及上下文；区分扫描候选与编辑判断。
- [B] R3 事实、引文、引用、技术含义、真实不确定性和有用的作者语气得到保留；不编造缺失证据。验证：将受影响段落与原文比较，检查每项变化的主张或受保护片段。
- [B] R4 结论针对表达质量，不含作者来源概率、通用句长判据或绕过检测器的技巧。验证：检查总评、理由与改稿是否包含这些无依据推断。
- [B] R5 所选模式的交付物完整，即审校发现或全文改稿，并准确说明局限。验证：读回输出，核对全部所需部分，确认 `result-only` 正文未混入审校记录。
- [B] R6 遵守已声明的轮次预算；每项已接受成果和要求都有最终台账状态及证据或理由。验证：核对已完成及待处理范围；预算耗尽时，未达成的必需工作保持 `blocked`。
- [B] R7 按固定规则与已选文体检查；扫描器使用保持本地、只读，并理解配置、排除区域与候选性质。验证：检查实际规则版本、文体、输出及输入、配置；缺少适合的运行时或文本文件时，记录有界人工检查。每篇草稿不再自建 SOP 或词表。
- [A] R8 重要的候选排除判断和有效表达在有助说明决定时得到保留。验证：在报告或工作记录中保留简短理由；不添加凑数赞美，也不记录每个无害命中。

## 何时停止

所选交付物已交付、受影响上下文已检查、全部适用的阻断性要求都有完成证据时停止。
保留的合理表达无需清零。

完成一次语义阅读、最多一轮修改和一次受影响上下文验证后，停止继续润色。
若必需检查仍未通过，报告可用结果、未完成项，以及缺失的最小输入、能力或决定。
这些要求保持 `blocked`；预算耗尽不代表完成。空输入或不可读输入只产生缺失输入报告，
不能判为表达无问题。

## 输出契约

- `audit`：范围及覆盖说明、有依据的表达总评，以及按
  `位置 | 原文精确摘录 | 缺陷及读者影响 | 等级 | 最小修法` 组织的发现。
  纳入重要的保留或待定判断、简短台账和停止条件。不要为凑报告而制造问题。
- `edit`：上述报告加完整的最小改动版文本；审校说明放在面向读者的正文之外。
  区分已修改的措辞与尚未解决的来源或事实问题。
- `result-only`：按所需格式交付完整改稿。台账和检查留在工作记录，不进入正文；
  未获授权不另建附属文件。输入或能力不足使全文无法交付时，在正文之外给出必要的覆盖或阻碍说明，
  不把部分结果呈现为完成。

需要有限范围的练习时，使用双语[虚构审校案例](examples/review-cases.zh.md)。
