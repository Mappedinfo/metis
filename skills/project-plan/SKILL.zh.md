# project-plan

[唯一发现入口](SKILL.md)。本文件为中文自有主稿，入口为同步英文译文。两份共享
方法、边界、验收与预算；发现文件名不赋予语言语义优先权。来源与变化见
[PROVENANCE.md](PROVENANCE.md)。

## 何时使用

适用于从明确目标创建计划，或让既有接受计划可执行。需要复盘进展原因、经验和
新方向用 `review-advance`；研究问题未定用 `research-question`；需要详细输入／
输出合同的 AI 拆解用 `research-taskbook`。可利用已验证复盘结论，但计划维护不
授权执行全部下游任务、删除历史或改变接受的研究决定。

## 方法

1. 从请求和项目确定目标及唯一当前状态入口，读取接受的里程碑、限制、保护区域
   和证据链接。复用既有计划或 issue 约定，不造竞争台账，不把 README 改成通用
   格式。只要求草案时不写持久项目状态。
2. 将原始要求逐项与实际证据对照。区分计划、已开始、阻塞、完成和移除。启动消息
   或文件存在不是完成证据，找接受的检查。保留数量、范围及兼容修订。当前记录
   与已核来源冲突时说明冲突和拟修正，不能静默以最新文字作权威。
3. 把活跃项写成可执行动作：具体动词、输入、交付／检查、依赖；负责人和日期
   只用已知内容。阻塞项说明外部依赖及最小解除条件，完成项绑定验证结果，移除项
   按需保留理由与重开条件。复用项目状态名，无约定时用 `[plan]`、`[doing]`、
   `[blocked]`、`[done]`、`[drop]`。
4. 按未解依赖排序，不按页面整齐排序。前置与独立工作分开，确定下个关键决定，
   并发按实际能力，不造期限或强制统一活跃项数。依赖未知结果的步骤保留条件性；
   详写眼前可检查步骤，后续留条件里程碑，不编完整执行路线。
   异构批处理或独立产物制作时，按共享的
   [并行生产指南](../metis-router/references/parallel-production.zh.md)写入共同契约、
   单元边界、容量证据和恢复条件。该条件引用不调用路由、不分配代理、不授权执行；
   生产规则只在共享指南维护。
5. 精简而不丢要求。合并重复时保留来源 ID，获准时将可复用流程移到既有参考。
   保留完成／移除证据、保护笔记和原始资料。短计划能看出当前状态、下一步和解除
   条件；缩短不能删接受的覆盖。
6. 对照起始要求和真实证据检查修改后的状态入口：依赖链接、done 的接受检查、
   计划仍未执行。另有执行授权时链接实际结果，不凭旧计划猜。报告实质状态变化，
   普通格式整理不需要新增决定。

为接受的任务与 R1–R6 维护一份验收台账，逐项记录 `done`、`blocked` 或 `n/a`，
附已核对证据或范围理由。方案与建议不能证明下游行动已执行。

## 验收要求

- [B] R1 接受目标和要求保留：逐项核对原始任务、数量和兼容修订。
- [B] R2 状态匹配证据：核对完成产物，计划／开始／阻塞／移除各自区分。
- [B] R3 活跃项有动作与依赖：核对交付、检查和最小解除条件；未知人名／日期保持未知。
- [B] R4 权威入口和保护内容保留：检查竞争台账、证据丢失及无关修改。
- [B] R5 维护不冒充执行或新增授权：实际动作和报告结果符合接受的范围。
- [A] R6 下个决定容易找到：检查任务顺序和当前能力，后续条件里程碑不盖过下一步。

## 何时停止

一次状态和证据核对，最多一轮限定修复及受影响项目复查。所求计划／差异和必需项
通过后交付。预算耗尽时说明已维护项目、未解状态及最小证据或决定。未知完成保持
blocked；计划写好不等于未来任务完成。

## 交付契约

在既有权威位置交所求计划或更新、精简的实质变化／证据记录，以及验收台账。只要
草案时交草案，不改台账。保留来源 ID、依赖和解除条件；提交、保存、计划与执行
只有实际发生时才报告。
