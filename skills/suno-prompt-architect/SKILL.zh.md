# suno-prompt-architect（Suno 提示词架构）

把用户给的主题——一句话、一个情绪、一个梗、一个场景——翻译成 Suno
Custom Mode 真正读取的两份输入：作为制作说明（brief）的 Style 提示词，
和以 `[方括号]` 结构标签承载编排指令的歌词。核心是转译而非代想：方向由
用户定，本技能把选定方向执行到两块内容可以直接粘贴生成。

## 适用与转交

适用：流行歌、短视频热曲、梗曲、氛围音乐的 Suno 提示词制作；上一轮生成
之后的 Style 描述或歌词标签修订；精确编排（drop 次数、段落长度）的
双字段对齐。

转交：实际音频生成与音色判断由 Suno 完成，本技能交付输入对；歌词作为
独立文字的文学性修改 → 文字编辑能力；乐理教学、混音工程、DAW 工作流
超出范围。

## 流程要点

1. **先锁一个方向**：Suno 的失败多半不是描述太少，而是描述互相打架——
   一首歌里同时塞进 EDM、摇滚、trap、抒情、女声、节日 drop，模型就找不到
   中心。动笔前锁定三件事：**主风格、听众该感受到什么、这首歌用在哪里**，
   并用一句话向用户复述："我会把「{主题}」做成 **{主风格}**，情绪
   **{核心情绪}**，主要用在 **{场景}**"。用户未指定场景时推断合理默认值
   （如"抖音短视频 30–55 秒""个人聆听""播客片头"）并声明是推断；主题
   明显支持多种风格时，同一轮给出至多 3 个方向供选择并记录用户的选择；
   用户已选定的方向不再重开。
2. **Style = 制作说明，不是营销文案**：堆叠的形容词会互相稀释成 prompt
   fatigue，位置越靠前权重越高——第一个词承载约 60–70% 的输出 DNA，
   **主风格必须放最前**。用英文写（Suno 对英文风格标签理解最稳），
   **4–7 个描述项**，总长 **150–300 字符**，骨架：

   ```
   [主风格/子流派], [核心情绪 1–2 词], [BPM 或 tempo feel],
   [核心乐器 2–3 个], [人声方向], [使用场景], [制作质感/混音特征]
   ```

   节奏写具体数值或明确感受（`128 BPM`、`mid-tempo`、`slow burn`），不只
   写"有节奏感"；人声方向含性别、音色、演唱方式（`breathy female vocal`、
   `raspy male vocal`、`spoken word`），纯音乐写 `instrumental, no vocals`；
   使用场景帮模型定能量层级与结构意图（`for short-form video`、
   `for late-night listening`、`podcast intro`）；不使用真实艺人名，用流派
   与特征替代；只留一个音乐中心，不堆互相矛盾的流派。
3. **歌词带结构标签**：歌词用提问语言（中文提问写中文词），除非用户另行
   指定；始终带 `[方括号]` 标签——它们是给模型的编排指令而非装饰，想要
   几次副歌就写几次 `[Chorus]`。默认流行骨架 `[Intro]/[Verse 1]/
   [Pre-Chorus]/[Chorus]/[Verse 2]/[Chorus]/[Bridge]（可选，情绪转折）/
   [Outro]`。副歌决定一首歌能否传播：短句、重复、口语化，植入一个能被
   单独拎出来的钩子短语；短视频场景总长压在 **30–55 秒**，精简为
   `[Intro]→[Verse]→[Chorus]→[Outro]`，让副歌在开头 **15–20 秒**内到达；
   编排事件用独立标签（`[Guitar Solo]`、`[Beat Drop]`、`[Silence: 2s]`）；
   行数不求对称，服务听感与钩子；纯音乐请求不写人声歌词，歌词字段只放
   结构标签（平台允许时留空）。
4. **可选：两层编排对齐**：用户要求精确编排（精确 drop 次数、段落长度）
   时，Style 末尾追加编排叙事（`arrangement: intro 4 bars, verse 8,
   chorus 8, drop 16, outro 4.`），歌词侧用小节数后缀（`[Drop 16]`、
   `[Outro 4]`）镜像同一套编排，两侧数目一致。
5. **类型模块：AI 口头禅梗曲**：用户要的是 AI 梗曲（口头禅 mashup）时，
   整首歌**只用 3–4 句口语口头禅**搭成——服务腔短语，如"当然可以，好
   问题""我会接住你""你说得对""让我想一想"。重复即歌曲，没有第二个
   主题。实测过的类型语法：**热开场**（第一句就是一嗓子，明显响于全曲，
   是 3 秒抓耳点）→ **短句重复** → **一段长独白 verse**（流畅、疏导腔，
   作反差）→ **音节碎切段** → **hook 陈述** → **谷**（近乎无声的一拍）
   → **尾声回声重复**，渐弱。咏唱句**不超过 7 个音节**，且独立成梗；
   副歌选最短那句。碎切段重复单字或音节（对 对 对 对／想 一 想），用
   独立标签（`[Stutter]`）＋逐字行标出，让 chop 网格在纸面上可见。此类型
   的 Style 词表：`spoken-word AI-voice chant`、`vocal-chop stutter
   edits`、`minimal sub-bass 808 bed, no bright hats`、`low-passed lo-fi
   mix`、`monotone synthetic vocal`，节奏写在 70 BPM 半拍区（碎切落在
   约 0.21 s 的音节网格上）；值得再给一个动态短语（`hot open shout,
   compressed verse, drop before final hook`）。这类歌成败在口头禅的
   选择：2–3 句真实、可被引用的短语，按流程要点 1 当作方向与用户一起定。
6. **自查后交付**：对照 R1–R6 检查草稿并修掉不合格项，再按固定四段格式
   交付（见交付物）。生成建议写明 Custom Mode 与写作时可用的 Suno 版本，
   并给修复规则：副歌不抓耳 → 保留歌词，只改 Style 的情绪/乐器描述重新
   生成；结构不对 → 修歌词标签，保留 Style。
7. **有界修改循环**：每个方向在首次交付后至多两轮修改；一轮 = 用户报告
   一次生成结果，本技能调整一个字段。预算用尽即报告已交付内容、仍未落
   地点与最小解锁条件（通常是换一个风格方向），不原地反复重生成。

## 需求（验收口径）

- [B] 单一音乐中心：主风格居 Style 首位，无互相矛盾的流派描述——读首项，
  扫其余各项是否含竞争流派标签。
- [B] Style 为英文、4–7 项、150–300 字符，节奏具体、人声方向明确（纯音乐
  为 `instrumental, no vocals`）——数项数与字符数，核对节奏与人声项。
- [B] 两个字段均无真实艺人名——扫描后以流派/特征描述替代。
- [B] 歌词至少含 `[Verse]` 与 `[Chorus]` 标签；纯音乐请求无人声歌词——
  扫描标签。
- [B] 副歌含可提取钩子短语；短视频场景下第一处副歌位于结构开头 15–20 秒
  内——读副歌并按标签顺序核对。
- [B] 交付与固定四段格式一致——发送前对照交付物逐段核对。
- [A] 要求精确编排时，Style 叙事与歌词标签的小节数逐项一致；[A] 主题支持
  多种风格时提供至多 3 个方向并记录用户选择；[A] 梗曲类型下，咏唱句
  ≤ 7 音节、副歌为最短口头禅、碎切段带独立标签与逐字行——数音节、
  扫描标签。

## 停止条件

完成 = 两块输入＋生成建议按固定格式交付，且各 [B] 项有通过证据。预算：
方向澄清一轮、方向选项至多 3 个、每方向修改至多两轮；超限即报告已交付
内容、未落地点与最小解锁条件，未完成项保持 blocked。本技能交付提示词而
非音频，实际听感在 Suno 内验证，如实说明，不承诺音质。

## 交付物

1. 主题理解一句话（注明哪些是推断）；2. Style 代码块（注明粘入 Suno 的
"Style of Music" 框）；3. 歌词代码块（注明粘入 Custom Mode 的 "Lyrics"
框，含结构标签）；4. 生成建议（Custom Mode、写作时可用的 Suno 版本、
"保歌词改 Style / 修标签"规则）。用户验证方式：两块直接粘进 Suno
Custom Mode 生成；收尾说明逐条给出需求的 done/blocked/n-a 与证据，并列出
未完成项。
