# concept-note

[唯一发现入口](SKILL.md)。本文件为中文自有主稿，入口为同步英文译文。两份共享
方法、边界、验收与预算；发现文件名不赋予语言语义优先权。来源与变化见
[PROVENANCE.md](PROVENANCE.md)。

## 何时使用

适用于读者需要理解或使用的概念、方法、指标、工具、数据集或标准。已有笔记可直接
修改，新笔记可能需要获准的来源收集。以系统解释一个对象为读者任务时，由本技能负责，
无论材料是否已有；以组织材料说明事件、历史或其他主题为任务时用 `source-brief`。论文论证
解析用 `taskbook-interpret`；多项研究共同支持什么用 `literature-synthesis`。本技能写
概念解释，不推断用户当前研究方向，也不凭知识整理请求修改知识库索引。

## 方法

本场景持续负责概念笔记的完整交付，必要的来源收集、组织、起稿与审校不自动转移
负责人。开始时读取[共同写作判断](../source-brief/references/writing-foundations.md)，
内部完成情境和信息组织；模块复用不等于调用另一个成文场景，也不新增策划文档。
仅请求定义、提纲、审校或局部修订时，保留该操作范围。

1. 确定笔记要帮助读者做什么：对象、已有知识，以及希望支持的判断或操作。区分
   概念、产品、实现与历史版本。按请求选择语言、深度和保存位置；修改时保留原文
   有用的结构及作者措辞。
2. 补充主张前先建立来源映射。标明实际查看的是原始材料、官方文档、二次解释、
   摘要还是元数据；关键主张保留位置、日期和版本。全文可用不等于全文已查。
   当前行为、价格或标准会影响笔记时，核对当前权威源；访问缺失时记录缺口，不补造。
3. 用一句普通语言定义开篇，再用一个贯穿解释的具体例子说明为什么需要这个概念。
   数值概念先算小例子再形式化，公式旁定义每个符号、单位及分母，并解释输入变化
   如何影响输出。自造数字明确标为教学数据。非数值对象用具体事件或任务呈现机制。
4. 把机制与适用条件一起讲清。区分测量、优化、预测和决策；连续目标变好不保证
   阈值指标变好，输出概率不自动证明校准。说明理解或使用所需的关键假设及其后果；
   当真实失败情形或反例能帮助判断边界时，用有依据的例子说明，并保留必要的科学证据。
5. 需要帮助判断适用条件时，沿一个明确的比较轴选择现实替代方案：指标比较相邻度量，软件比较可用流程，
   方法比较假设和取舍。说明没有该对象时会怎么做、会损失什么；区分有用、特定条件
   下必要和可选。历史、当前发展、上下游只在有助理解或使用时展开；用户明确要求
   的维度必须覆盖，缺少必要来源时保持 blocked，不能默默省略。
6. 沿例子检查：读者能否辨认对象、跟上推理、解释输出并判断何时使用？逐项核对
   关键事实的来源位置，检查算术、符号、适用范围和比较。章节齐全不能证明解释
   易懂。只有请求或实际语言问题需要时使用 `prose-audit`，共用本次审查预算。

为接受的任务和下方 R1–R6 维护同一份验收台账，逐项记录 `done`、`blocked` 或
`n/a`，附实际产物的位置或范围理由。不能用 `n/a` 免除用户要求；方案不能证明执行。

## 验收要求

- [B] R1 对象与读者任务明确：检查定义是否说明解释对象及用途，未混同相邻对象。
- [B] R2 例子能检验机制：核对中间计算或事件顺序、符号与教学数据标记。
- [B] R3 关键事实可追溯：沿来源映射核对位置、证据级别、实际查看范围及必要版本日期。
- [B] R4 假设及适用的替代方案有作用：核对关键条件及其后果；需要反例或比较时，检查依据及比较轴。
- [B] R5 保留请求维度与修改要求：对照接受的请求，必要支持缺失时标为 blocked。
- [A] R6 笔记无需反复打开原文也可使用：按读者任务检查局部定义、衔接与应用清单。

## 何时停止

做一次内容和证据审查，最多一轮限定修复，再检查受影响主张。笔记、来源映射和适用
必需项通过后交付。需要补来源时，对未解主张做一批有界收集；进一步工作由新请求
决定。预算耗尽时报告已完成部分、未完成要求和最小缺失来源或决定，必要未解项保持 blocked。

## 交付契约

交付所请求的笔记或完整修订、附核对位置与日期的来源映射，以及验收台账。按请求
提供例子深度与限制。仅对话解释无须建文件；要求保存时给实际路径。教学内容与
来源报告的事实分开，未验证的当前事实保持开放。
