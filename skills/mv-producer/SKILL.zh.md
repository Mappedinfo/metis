# mv-producer（主题 → 歌 → MV）

从**主题**或**一首已完成的歌**——音频文件＋它演唱所用的歌词稿——做成音乐
视频（MP4）。主题先走 Stage A 写歌包、生成音频；成品音频从 Stage B 开始。
歌词烧进画面、场景卡在实测的音乐分段上、动效跟着歌曲能量走。
视频用代码渲染而非拍摄：确定性 HTML 渲染器从时间值画出每一帧，无头浏览器
逐帧截图，ffmpeg 合成并携带原曲音频。两个决策按合同分离：**画幅比例**是
出产尺寸，**视觉风格**是另一个独立选择、有自己的默认值。

## 适用与转交

适用：从主题生成歌曲再做 MV；给成品曲目做 MV／歌词视频；给 Suno 生成的
歌配画面；在渲染器源码上按修改意见（歌词、配色、节奏）低成本重渲染。
只要歌、不要 MV 时，Stage A 交歌包后停，不渲染。

转交：实拍、合成镜头、VFX 素材超出范围——本管线画的是动效图形与文字
排版；给任意视频做字幕文件（SRT/ASS 交付）→ 字幕能力，不是自成一体的
MV。平台生成的快速可视化视频超出范围；本技能只做定制 MV。

## 流程要点

0. **先选阶段：主题 → 歌，或成品音频。** 成品音频＋歌词 → 直接 2；
   主题＋已配置 Suno API → 0a 写歌包、生成、下载选定 take → 2；主题但
   无 API → 交歌包（Style、标签歌词、62 小节预算），不假装生成。
0a. **歌曲阶段**：完整歌默认 1:50–2:10；144 BPM 62 小节（Intro 2、
   V1 8、Pre 8、Chorus 8、Stutter 4、V2 8、Pre2 8、Bridge 4、Final 8、
   Outro 4），第一副歌约 0:30；30–55 秒只是点名的 short-form。写 Style
   （英文 4–7 项、150–300 字符、主风格在前）、标签歌词（每段一个韵脚、
   末句落标题/钩子、音色在 Style）、标题；详见
   [references/song-stage.zh.md](references/song-stage.zh.md)。有 API 时从
   环境读 key，绝不打印/提交；建任务、限时轮询、下载选定 take、保留
   taskId/audioId；接口见 [references/suno-api.md](references/suno-api.md)。
   同任务优先用 API 的 timestamped lyrics 与 separate_vocal 分轨，否则
   走 2a；原混音留给 MV。不改选定 take，只做电平/真峰值安全。
1. **拆开两份合同：比例是尺寸，风格是风格**。用户报比例——常见 MV 诉求是
   **4:3 和 16:9**——那只是**出产／交付画幅**，绝不是风格简报（4:3 不等于
   复古，16:9 不等于电影感）。映射成像素即可：4:3→1440×1080，
   16:9→1920×1080，9:16（竖屏，被点名时）→1080×1920；用户给了精确像素
   以像素为准。视觉风格单独决策：用户点名就用用户的；没点名则应用**默认
   风格画像**——**现代**（干净版面、UI 级字体、自信留白）、**激情**
   （节拍驱动的动效、抖动、弹跳、快速入场）、**色彩**（高饱和多色、渐变
   能量、高对比主视觉）、**颜文字**（♥ ♪ ✧ (๑•̀ㅂ•́)و 等作粒子与剪辑
   标点）。复古、CRT、极简、胶片感都是需明示的可选项，记录为用户或需求
   的选择，绝不作为比例的副作用混进来。

   **默认画像的具体实现**。现代：全出血歌词海报；可选微 chrome（一枚
   chip 或一个量表）不得超过画面 10%，绝不演变成页眉／侧栏／字幕带。激情：
   每个重音用过冲缓动入场＋短促屏幕抖动；缩放脉冲锁死节拍；入场不超过
   0.35 秒。色彩：每个段落一块高饱和双色调渐变，段落边界硬切——切就是
   效果本身；快速闪词用色相轮换。颜文字：命中时纸屑爆开、副歌里低透明度
   环境漂浮、喜剧道具上的注释文字。喜剧道具一条视频只放一个——一个绑定
   歌词笑点的量表（副歌瞬间弹到 100%）比三个机灵的都耐看。

   **全屏动态字画像（meme-chant 与短视频参考的默认）**：歌词就是画面。
   不要固定底部字幕带、侧边仪表盘或卡片式 chrome；把整句烧进构图。每个
   镜头一个主字块（画面 35–50%），至多三档字号，涂鸦／emoji／ASCII 等
   次级元素 ≤20%。用堆叠、裁切、拆分、描边、半调、贴纸处理歌词；手绘
   记号与 emoji 是标点。每个镜头都有入、驻、出：字以 0.15–0.25 s 的步进
   逐词搭建，呼吸/漂移，再通过过渡交给下一个镜头。剪切率是结果，不是
   目标：0.8–6 s 一镜、约 0.2–1.2 次/秒都成立（长叙事 2–6 s 正常）；不设下限；硬切和全屏闪只留给
   drop 与 chop。9:16 参考就原生竖屏设计，绝不从 16:9 裁切。
   **PPT 失败模式**：固定底字幕；页眉＋侧栏＋说明的“幻灯片”；等重卡片；
   大留白小字；以慢叠化为主；三栏 UI；让表格／仪表盘承担歌词该干的事。
   任何静帧能被误认成 PPT，就不合格。

   **参考驱动改写**：用户给参考视频或说“像 PPT”时，先写风格卡：BPM 与
   分段能量、配色与字号层级、歌词位置（全屏／侧栏／字幕）、动效词汇、反复
   母题与参考刻意回避的东西。测运动而不只是剪切率：抽 10 fps 镜头内序列，
   算帧差基线，标出字如何逐词搭建、哪个角色/道具在动、背景如何回应前景。
   0.3 次/秒的窗口可能比 1.5 次/秒的静态海报更有生命。写下三条迁移规则
   与三条反规则；用原创资产重建语法，不复制参考的帧、画、字体或音频。
   风格卡与时间表放在一起，渲染后逐项对照。
   **能量编辑（需明确授权）**：本技能从成品音频开始，不制作歌曲。用户说
   BGM 太柔和／电子音太少时，给两个明确选项：(a) 交给歌曲生成能力做新歌；
   (b) 对原曲做**能量编辑**。选 (b) 需明确同意、保留原文件，并说明这是
   编曲／remix，不是重制：高通原曲低频；用 chroma 测调；加四拍底鼓、同调
   sub／808、hat、clap、同调 synth arp、riser、impact、glitch；对原曲做
   sidechain；以参考的响度与 crest 为目标；检查真峰值与削波。同时交付原曲
   与硬编版，附频段／响度证据。要换歌就停在交接点。
**用户设计偏好（默认，强简报可覆盖）**：先人声后画面（先按 2 审查实际
演唱，再按 2a 用核验过的 API 或 vocals 词级时间戳卡歌词；RMS 只排场景）；整首是单位（两分钟歌做两分钟
MV，60–75 s 是单独交付，不静默截断全词；不改选定的 take，只做电平/
真峰值安全）；长叙事全屏动态字（两分钟 20–30 镜、2–6 s、0.2–0.35 次/秒、
4–6 个硬切）；字是画面、贴在人声上（主字块、整行可见、无底字幕、不裁
末字、长句一行一卡；脸/线/道具不盖字）；语义材质要做机制（五彩斑斓的黑
= 黑底 + 光谱 clip-path 扫入，透明一点的灰 = 真 rgba/棋盘格 + α 读数；
浅灰填充不是透明，预填彩卡不是黑变彩）；stutter 是短 chant，不盖下一句
（1.4 s 六个对字可能优于十一个盖住“我这就改”）；红线/脸/点阵/字跨镜
延续，最后落在一个巨字/收据；可读性优先，渲染前做字号/几何检查。
详见 [references/semantic-effects.md](references/semantic-effects.md)。

2. **先审查实际音频，再做设计**：先完整听选定音频、对照歌词稿，记录
   实际时长、唱词及其顺序、漏唱／重复／改词、人声起止和停顿。保留原稿，
   把演唱差异和存疑词写进时间表；副歌提前或主歌缺失时，场景顺序跟随
   已核对的实际演唱。原稿标签、要求的 BPM 和固定拍网格都不能证明实际
   唱了什么、何时开唱。

   **可用音频优先复用**：已有音频符合已接受的歌曲要求时，保留该版本，
   调整动画与歌词时间；节奏漂移或编排不同本身不构成再次付费生成的理由。
   只有音频本身不满足目标时，才在既有生成授权和预算内考虑重新生成。
   时间证据绑定选定版本的 ID 或文件哈希；换音频后重新对齐。

   ffprobe 拿时长；`silencedetect` 找硬停顿；解
   单声道 PCM 算 0.25 s 步进的 RMS 能量包络，定位段落真实起点——前奏、
   主歌入口、副歌爆点、间奏、尾声。包络只给段落能量，不是可靠的行时钟。
   据此写场景时间表：每个场景边界引用实测时间；生成/自由节奏人声的行级
   cue 走 2a，绝不用包络峰或段落均分。ASR 不可用时退到段落级并说明，
   不假装行级对齐。用起始点密度尖峰定位碎切段，并把段内起始点间隔量化
   （真实网格读数 ≈0.21 s / 0.42 s）；这个量化网格——而不是名义 tempo——
   才是闪烁网格。

2a. **生成/自由节奏人声：先分轨，再逐词对齐。** Suno 式输出不是节拍器：
   人声可能晚进、抢句、拖字，副歌和 stutter 还会交错。先把混音拆成
   vocals/instrumental（Demucs htdemucs 或等价两轨分离）；原混音留给
   MV，人声轨只作时间证据。若曲目来自同一 Suno API 任务，优先用 API 的
   timestamped lyrics（alignedWords: word/startS/endS/success）与
   separate_vocal 分轨。API 返回成功不等于对齐可靠：无效／零时长项、
   重叠和过短词项都要对照音频检查；证据缺失、不可靠或曲目来自外部时，
   用本地分轨 + ASR 补查，保留未解决区间。
   对 vocals 跑本地词级 ASR（Whisper /
   faster-whisper）；已接受的歌词稿仍是显示文本，ASR 只给时间。把已知
   歌词中确认唱出的行按实际顺序对齐到词级时间戳，不把漏唱的主歌硬塞进
   空档：行首=该行第一个唱词，行尾=下一行行首或该句
   唱完；不要均分段落。写每秒表：秒、段落、镜头、当前歌词行、人声
   dBFS、ASR 词；镜头窗口从行首来，画面不得跑在人声前面；长前奏、
   post-chorus、间奏是 hold，不编词。stutter 用真实 chant 区间，在下一
   句前结束，不盖下一句。ASR 不可用就声明段落级降级，不声称行级精度。
   具体命令见 [references/audio-first-timing.md](references/audio-first-timing.md)。
3. **按核对后的实际演唱编排 cue**：`[方括号]` 结构标签（[Intro]/[Verse]/
   [Chorus]/[Outro]…）只是原稿的分段标签；场景按 2 的审查结果分组，
   确认唱出的歌词逐行按实际顺序写 cue，包含重复，起止窗口来自时间表。
   生成/自由节奏人声的行窗口来自 2a，绝不用段落均分；钩子句给主视觉排版时刻（巨字坠落、整屏强调），不再叠气泡。
   已知歌词沿用被接受的措辞，核实的改词单独记录，不把嘈杂 ASR 当作改词
   依据。无歌词段
   （纯音乐前奏、间奏）用界面风味或刻意的静止，绝不编造词句。

   **剪辑画像——meme-chant 闪烁（梗曲闪烁）**：AI 口头禅 mashup 的节拍
   网格不是 tempo 假设，而是实测的音节 chop。取最密段落的起始点间隔，
   闪烁跟随该网格（如每音节约 0.21 s、每短语单元约 0.42 s），其余段落
   按拍闪整句；碎切段闪被切碎的那个词本身——一次一词，不是整行。热开场
   喊话给整屏重击；谷位在最后一个 hook 前保持近黑一拍。配色与字体仍来自
   生效的视觉画像（默认或用户覆盖），本画像只管剪辑语法。
   **运动设计——让镜头动，不是让幻灯片切**：剪切是过渡，不是内容。参考的
   能量来自镜头内：一句词逐词搭出来，笑脸表情变化，手托住字，文件夹打开，
   背景扫描回应。每镜三阶段：入（逐词/遮罩/滑入/缩放/画入，不要直接 pop
   成完成海报）、驻（字漂移呼吸、道具绕行、镜头缓推、背景流动，不能静止）、
   出（match cut/擦除/遮罩/形变/线过渡，或在 drop 上刻意硬切）。每镜至少
   一个前后景因果关系：视差、遮挡、反应（点阵为字让开、笑脸弹开、影子跟随
   镜头）、共享运动（红线/字跨切延续）、颜色溢出、跟随字的光。纯色底+居中
   字不算互动。带一个母题/道具/线/色/字跨镜延续；不要每拍换一张新海报。
   运动预算：一主、一次、一环境；不要所有元素同时动/闪；每段最多一次全屏
   闪/反相；留呼吸；快速 chop 只给 stutter。视觉污染失败模式：每拍新海报、
   持续全屏闪、所有层一起动、无因果特效、背景静止、前后景无关、没有呼吸、
   切得比眼睛读得快；5 s 序列像带频闪的 PPT 就不合格。运动审计：抽 5 s
   10 fps 序列，算镜头内帧差基线与切点，数同时运动元素，检查每镜入/驻/出
   与至少一个前后景互动，检查过渡而不只看静帧。长叙事：两分钟故事歌不是
   把 60 秒拉长——20–30 镜、2–6 s、0.2–0.35 次/秒、4–6 个真 drop 硬切；
   长前奏/间奏是 hold。stutter 在下一句前结束，下一句不能被盖住。

4. **写确定性渲染器**：一个画布尺寸的 HTML，暴露 `seek(t)`——从时间到
   完整帧的纯函数。所有位置、透明度、reveal、粒子轨迹都由 `t` 计算
   （种子随机、分段缓动），不用 CSS transition、不用墙钟动画。这才使得
   帧级精确渲染、任意时间点探针抽查、改后廉价重渲染成为可能。基础字体用
   系统 CJK（如 PingFang SC）；展示字体是明确的风格决策。每个场景都是
   时间表数据的函数——改节奏是改数据，不是改编排代码。
5. **渲染帧、合成、为 end card 补静音**：无头浏览器按 24–30 fps 逐帧截图（9:16 字清晰用 30）
   （JPEG 质量 ≈92 足够，反正要过 H.264），ffmpeg 合成：`libx264 /
   crf 18 / yuv420p`、AAC 192k、`+faststart`。结尾有 end card 时用
   `apad` 把容器延长过歌曲结尾、`-shortest` 修剪，让卡片停在黑场而不是
   被截断。渲染脚本与合成脚本放在渲染器旁边——MV 的事实源就是这三个文件
   加时间表，后续每次修订都是重跑它们。
6. **在编码成品上验收，轮次有界**：别只看源帧——从编码后的 MP4 抽关键
   场景静帧（前奏、主歌、副歌爆点、间奏、尾声、end card）实际查看；
   ffprobe 核对流的编码、宽高、帧率、时长与要求的画幅、实测歌长；响度
   扫描确认音轨真的带上了。全量渲染前，用低成本声画预览核对人声入口、
   段落换序、stutter 和存疑区间，确认歌词、对话与转场跟随人声；编码后的
   MP4 再查这些位置及合成引入的音画偏移。静帧和时间计算不能单独证明
   听感同步。全量渲染前先做数值几何检查：抽每个场景中点
   探针帧，并在 DOM 里断言包围盒留在安全边距内、不与 chrome 重叠——数值
   断言比逐帧目检更便宜也更严。不合格就改渲染器、重渲染、复检。每次交付
   至多两轮视觉修复；超出即报告仍未落地点与最小解锁条件（通常是一个
   属于用户的风格或节奏决策）。**PPT／视觉中心／运动审计**：断言没有
   固定底字幕或侧栏（除非明确要求）；每个 beat 的字号 ≤3 档；最大字块
   ≥画面 35%、中心落在中间 60%、只有一个焦点；记录剪切率但不优化它。
   每镜断言入/驻/出与至少一个前后景互动；抽 5 s 10 fps 序列，检查帧差
   基线、同时运动元素数与全屏闪频率；从编码成品抽至少十个静帧，不只抽
   段落中点。

## 需求（验收口径）

- [B] 画幅比例只是出产尺寸，不从中推断任何风格——渲染器画布等于所要求
  比例的映射像素；风格决策单独成文。
- [B] 用户未点名风格时，应用并记录默认画像（现代、激情、色彩、颜文字）；
  meme-chant／短视频用全屏动态字画像，默认没有固定底字幕——交付物写明
  生效画像或用户覆盖，且渲染中无默认字幕带。
- [B] 已知歌词保留被接受的措辞，烧录顺序跟随确认的实际演唱，记录漏唱、
  重复及核实的改词；歌词是画面主体，独立底字幕可选——cue 清单同时对照
  歌词稿与实际音频，检查全屏静帧，披露存疑文本。
- [B] 场景边界来自实测音频；歌词 cue 窗口来自核验过的 API 或 vocals
  词级时间戳（或明确声明的段落级降级）——时间表记录选定音频版本和演唱
  审查结果，每行有对应证据；不以原稿顺序、固定 BPM 或段落均分替代测量。
  保留声画预览与编码成品同步检查结果，披露未解决区间和降级，不声称未测
  得的精度。
- [B] MP4 画幅与长度符合要求、携带原曲音频、为标准可播放流（H.264
  yuv420p＋AAC、faststart）——对编码成品跑 ffprobe 与响度扫描。
- [B] 在编码成品上抽查关键场景静帧并修复发现的问题——列出抽查场景与
  结论。
- [A] 默认画像下，emoji／颜文字作为动效元素出现，不只是静态装饰——
  副歌静帧可见；[A] 渲染器确定性：同一 `t` 渲染出同一帧——同一时间戳
  重渲染两次比对；[A] meme-chant 画像下，闪烁时刻跟随实测 chop 网格而
  非固定间隔——抽样闪烁时刻对照时间表网格项；stutter 在下一句前结束且
  不盖下一句。
- [A] 高能／参考驱动剪辑达到运动与视觉中心目标——每镜有入/驻/出与至少
  一个前后景互动；剪切率只作结果记录（约 0.2–1.2 次/秒；长叙事
  0.2–0.35，不设下限），硬切/全屏
  闪只给 drop 与 chop；每个镜头一个 ≥35% 的主字块、≤3 档字号。
- [A] 不出现静态海报序列：每镜都在动并带连续性——5 s 10 fps 序列可见
  镜头内运动与过渡/共享母题；没有一镜是完成海报停到切点。
- [A] 视觉污染有界：每段 ≤1 次全屏闪/反相、≤3 个同时运动元素、至少
  有一部分慢镜/呼吸镜——运动审计计数与 5 s 序列复核。
- [A] 未明确要求时不出现固定底字幕或侧栏——DOM 无字幕带，编码静帧为
  全屏构图。
- [A] 做能量编辑时保留原曲并同时交付原曲与硬编版，附调性／响度／真峰
  值证据。
- [B] R15 歌词点名的材质/光学状态必须做成机制，不是换色或说明字幕——
  验证：黑变彩从黑底开始、光谱 clip-path 扫入（起始/中段/结尾静帧仍见
  黑）；透明用 rgba/opacity 叠在棋盘格上且下层可见；浅灰填充或预填彩卡
  不合格。
- [B] R16 整行歌词可读：不裁末字、脸/线/道具不盖字、长句一行一卡——
  验证：字号/几何探针 0 问题；每个 V2/长句场景的编码静帧。
- [B] R17 MV 覆盖交付歌曲与选定 take；非明确要求不截断、不改编——
  验证：时长与歌曲一致，或点名的短版作为单独交付；音频是原混音，仅做
  电平/真峰值安全。

## 歌曲阶段需求（S1–S11）

仅当请求 Stage A 时适用；从成品音频开始时标 n/a。

- [B] S1 单一音乐中心：主风格居 Style 首位，无竞争流派。
- [B] S2 Style 为英文、4–7 项、150–300 字符，节奏与人声方向具体。
- [B] S3 两个字段均无真实艺人名。
- [B] S4 歌词至少含 Verse 与 Chorus 标签；纯音乐无人声歌词。
- [B] S5 副歌含可提取钩子；完整歌 1:50–2:10、第一副歌约 0:30。
- [B] S6 交付符合歌曲阶段交付物。
- [A] S7 精确编排时 Style 叙事与歌词标签小节数一致。
- [A] S8 主题支持多风格时给至多 3 个方向并记录用户选择。
- [A] S9 梗曲咏唱 ≤7 音节、副歌最短、stutter 独立标签与逐字行。
- [B] S10 完整歌不是 30–55 秒骨架；short-form 必须明确点名。
- [B] S11 使用 API 时从环境读 key，绝不打印/日志/提交；建任务、限时
  轮询、下载并校验选定 take；不改 take。平台 MP4 接口不属于本工作流；除非
  用户明确要求该单独交付，否则不调用。

## 停止条件

完成 = 所要求画幅的 MP4 存在、流验收通过、编码成品抽帧通过，渲染器源码
＋时间表交付，完整覆盖交付歌曲（或点名的短版单独交付），各项 [B] 有证据。
若请求 Stage A，歌包、选定 take、taskId/audioId 及所用 timestamped lyrics/
分轨也交付。若只有主题且无 API，歌包就是交付物，不假装生成。预算：每次交付至多两轮视觉修复；风格方向
确实未定时至多一轮提问。超限即交付已通过部分，写明剩余视觉问题与最小
解锁条件（如"用默认现代画像或点名一个风格"），未完成项保持 blocked。
MV 从交付歌曲渲染。重制音频超出范围；明确要求的能量编辑属于编曲
（保留原曲、同时交付两版、测调性／响度／真峰值），如实报告；要新歌则
交接。

   timestamped lyrics/分轨；若做能量编辑，原曲与硬编版及调性／响度／真峰值

   MP4；时间表让修改意见可以指到具体时刻（"副歌在 23 s 爆"），得到定点
