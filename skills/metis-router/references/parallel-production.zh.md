# 并行生产

[英文对应稿](parallel-production.md)。本指南为中文自有主稿，英文稿同步维护方法、
边界和验收。公共规则仅在此维护；`project-plan` 和宿主路由按需引用。

## 适用条件与先行判断

异构批处理或多项产物制作开始前，检查能否拆成可独立交付、验证和重跑的生产单元。
按实际格式、处理器、模块或来源分组，不按文件数量机械分配代理。先读获准的代表
样本，确认差异，再固定处理规则；未知类型进入限定探查，不让各代理自行猜测含义。
已有接受计划时只补齐执行划分，不重开已定目标。单项、紧密耦合或很小的工作可
由一个代理完成；没有可用代理时仍保留单元边界，顺序执行。

本指南规定生产组织，不授予启动代理、获取新来源、写入、发布或新增调度器的权限。
审查与修复仍使用路由入口的 map–freeze–reduce 预算，不借生产重试延长审查轮次。

## 六项生产约束

1. **独立产物。** 每个单元有稳定 ID、获准输入、依赖、自己的候选产物、验收条件
   和最小阻塞条件。输入识别、计算、渲染、整合可分阶段；先交付代表产物再扩到同类。
   共用实体来源由一个读取阶段提供可复用的规范结果；在保留版本和筛选口径的前提下
   避免重复读取、重复计数。不能独立验收的部分留给共同前置阶段或协调者。
2. **共享契约。** 开工前冻结最小共同接口：字段／结构、观察单位、标识与关联键、
   必需语义、适用的坐标系／单位／时间口径、缺失及无效值、来源证据、版本、产物
   命名和验收。类型处理器实现同一接口，保留类型特有字段；不得为合并方便抹平差异。
   共同处理逻辑由单一负责人维护，单元提交适配器和契约测试，协调者核验后整合。
   契约改变先评估影响，再形成新版本，不让工作中的代理各改一套公共接口。
3. **写入边界。** 每个写入单元独占明确文件或候选目录；共同索引、清单、共享代码
   及正式切换由一个负责人串行完成。核对实际路径、链接目标与共用缓存，路径名称
   不同不代表写入独立。重叠单元排队，仅依赖它们的工作等待；其余独立单元可继续。
   保留已有修改和正在运行的任务，隔离验证后再合并，不在共享工作区竞争覆盖。
4. **资源预算。** 分别核对代理上下文与计算作业的容量：当前工具、会话是否允许
   子代理、实际空闲代理槽位，以及内存、CPU、磁盘、I/O 和远端连接限制。代理数量
   不等于重计算进程数；调查和轻量适配可并行，重作业按已核实预算限流。声明每单元
   的时间、重试、读取／输出上限和并发总额，不硬设通用代理数。容量未知时先小样本
   测量或顺序执行；工具可见和理论上限不能证明当前有空闲容量。
   **自设上限可被质疑并实测上调。** 既有并发或资源上限是历史设定，不是既定约束。
   用户质疑吞吐、排队时长或"为什么这么久"时，先实测当前 CPU、内存、磁盘与 I/O，
   再在同一轮把上限调到实测支持的值并说明依据，不重复索要授权；只有实测显示会挤占
   他人或共享资源时才回落。
5. **失败隔离。** 按路径、格式、字段、语义、关联和资源等原因记录失败；失败单元
   及其依赖暂停，已验收的独立结果继续保留。限定探查失败样本，补充该类型处理器和
   回归检查后再试。重试遵守既有预算；耗尽时说明具体阻塞与最小解除条件。不得把
   失败项静默丢掉，或用占位产物冒充完成；最终逐项对账全部接受的覆盖。
6. **增量重跑。** 各阶段保存输入内容、筛选条件、契约、配置、处理器及共同依赖的
   指纹和验收证据。只复用指纹匹配且验收仍有效的结果；修改从最早受影响阶段失效，
   重跑该单元及依赖闭包，未受影响项不重算。渲染变化可复用有效读取／计算结果；
   共用接口或依赖变化可能使整批相关结果失效，不能靠缩小指纹逃避重建。缓存记录
   不自动代替实际来源核验，不关闭完整性检查来加速。

## 持续生产与结果浏览（条件适用）

当用户需要边生产边检查结果时，将“已发布结果持续可浏览”作为独立交付要求。
这也适用于一个长任务，不以异构、多代理或整批生产为前提。先建立代表结果的
可浏览路径，后台继续生产并逐项开放；保留最终全量覆盖和验收，不把阶段展示
说成整体完成。没有这种使用需求时，不额外建立工作台或更新通道。

- **分离生产、发布和读取。** 生产者写候选；发布步骤核对该单元的结构、资源
  完整性和版本一致性后切换入口；只读接口和前端读取已发布版本。正在写入的
  文件、生成器代码和任务锁不成为展示依赖。先复用已有机制，逻辑分离不要求
  新增框架、队列、服务或调度器。基础预览通过与科学／来源独立验收分别标识。
- **轻目录与单元入口。** 总目录保留完整预期集合、轻量摘要、状态与单元引用；
  单元入口只含当前版本、图层／指标／时间选项和资源引用。详细证据、大几何、
  数值和成员列表按需读取、分片或分页，共用证据以稳定 ID 和哈希引用。首页和
  单项请求不得以加载所有详情、检查所有产物或全批通过作为前置条件。一个大对象
  或坏单元只影响相关请求，完整明细仍可追溯，失败项不从总覆盖中消失。
- **独立发布与兼容。** 每单元有稳定 ID、不可混读的结果修订和资源清单；新版本
  完整检查后原子切换该单元入口，失败保留仍有效的旧版本。改变生产代码不能直接
  替换正在服务的读取器或使已发布结果全局失效。API／数据契约不兼容时，保留
  已服务契约，在候选环境核验新读取器和前端后再切换；只失效实际受影响的依赖。
  已有证据判无效的旧结果须单项撤回或明确标错，不能借回退继续称为有效。
- **轻量发现更新。** 按实际延迟和规模需要选择版本摘要轮询或已有推送通道。
  只通知变化的单元 ID、修订与状态，前端只刷新受影响内容，不反复扫描完整证据。
  通知可丢失或重复，版本复查能补齐；不硬设刷新周期，不因一次更新重置筛选、
  选择、缩放或键盘焦点。保留预算内的本机缓存，旧版、候选和传输暂存共同计费。
- **故障期间继续浏览。** 生产者暂停、单元失败或刷新请求失败时，仍有效的已发布
  结果和已加载／缓存内容保持可用，标清版本、更新时间与新任务状态。尚未缓存的
  内容不可凭空离线提供；显示暂不可加载，而非清空无关结果或把错误解释为空间未知。
  跨单元合成视图只等待其真实依赖，保留并标注上一有效修订，独立单元可继续开放。

初建或实质改变持续浏览链路时，实际验收：生产者在运行／暂停时浏览旧结果；新单元增量出现；一个
单元损坏不阻塞其他单元；刷新失败保留有效内容和用户状态；不兼容候选不能替换
在用契约。检查当前最有后果的状态恢复，并记录哪些路径实际运行、哪些仅为计划
或模拟。既有链路的小改复用仍有效的契约与证据，仅复查受影响路径；不能用旧
检查证明已变化的路径。代码分目录、文件存在或构建通过不能代替持续可用性验收。

## 分配前的单元表

协调者记录共享契约的版本和位置，再为每单元填写：

| 项目 | 必需内容 |
| --- | --- |
| 单元与依赖 | 稳定 ID、处理类型、前置单元及当前输入证据 |
| 产物与写入 | 候选产物、独占路径、共同文件的唯一负责人 |
| 预算与验收 | 实际容量依据、每单元限制、产物检查与整合检查 |
| 恢复 | 阶段指纹、失败类别、可复用检查点、受影响重跑范围 |

适用持续浏览时，另记录已发布修订／读取入口、轻量更新通道、兼容边界与故障期间
可浏览的证据；这项交付不等待整批验收。

先检查契约与写入／容量事实，再分配实际可独立的单元。代理完成只证明其报告状态；
协调者检查真实产物、冲突、来源和全量覆盖，统一更新清单。候选验证失败时保留
当前有效批次。计划表完成不等于生产完成，也不证明运行时已读入本指南。

## 受影响范围示例

一个获准批次包含边界向量和计数表。先确认各自几何或观察单位，共享来源与输出
契约；两个处理器写入各自候选目录，共同清单由协调者更新。计数表出现字段编码
错误时修复表处理器，只失效该表的读取及下游产物，保留通过验收的边界结果。
若共同关联键规则改变，两类依赖该规则的结果都须重验。会话禁止子代理时，同样
的单元表顺序执行；它不成为绕过会话限制的理由。
