# pdf-annotater-researcher（研究论文 PDF 精读标注）

把一篇 born-digital 的研究论文 PDF 做成"打开就能逐段读懂"的标注版：在 PDF
文件本身写入原生注释对象——高亮锚点＋页边弹注＋书签导航——覆盖每个正文段落、
承载论证的关键句、每张图、每张表和每个公式，并附可审计的覆盖率报告。
不交付替代性的独立摘要文档。

## 适用与转交

适用：给已有 PDF 做原位阅读标注；把下载的论文归入项目文献库并随文件附带精读
标注；让一篇读不动的论文变得可回头查阅。

转交：只回答论文内容、不改文件 → 论文解读／文献问答能力；从 DOI/arXiv/题名
获取 PDF → 论文获取能力；判断稿件能否投稿 → 稿件评审能力；修改用户自己文本的
语言 → 文字编辑能力；扫描版 PDF（无文本层）超出范围，检测到即报告阻塞。

## 流程要点

1. **归位原文**：把 PDF 移到用户指定的项目位置（通常为 references/ 类目录），
   文件名不变。所有标注先写在临时副本上，验收通过后才覆盖项目文件——绝不
   在唯一副本上直接写。
2. **先读完，再写注**：`pdftotext`／`page.get_text("words")` 全文逐页读。
   双栏文本按栏存储；提取文本的"页"与视觉页可能错位，段落跨栏跨页时用渲染
   图核对边界；印刷页码与物理页码差一（封面页），所有标注一律用物理页。
3. **图表必须看图**：渲染含图页面并实际查看后再写注。图题不会告诉你混淆矩阵
   的类序，也不会告诉你框架图怎么读。图注三件事：画的是什么、怎么看
   （轴/面板/颜色/矩阵方向）、支撑正文哪条主张。
4. **先建方案再动笔**：标注写成 JSON 方案（字段与各类注释写法见
   [plan-schema](plan-schema.md)）。覆盖每个正文段落＋段内关键句＋全部图表＋
   每节导读＋封面总导读＋（读者有明确项目时）少量与项目关联注。参照密度：
   19 页双栏论文约 100–150 条，其中约一半是段落注。注释用读者声明的语言，
   术语、符号、数值保留原文；每条两三句：说什么、为什么需要、证据是什么。
5. **副本上应用**：

   ```bash
   uv run --with pymupdf python <skill-dir>/scripts/apply_annotations.py \
     --src <项目.pdf> --out /tmp/annotated.pdf --plan plan.json \
     --author "Close reading" --report /tmp/coverage.json
   ```

   每条 = 一个高亮 + 一个弹注；可选书签；注释文本以 PDF 字符串存储，中日韩
   文字在 Preview／Acrobat／WPS 中直接可读，无需嵌入字体。弹注图标固定钉在
   页边（左栏→左边距、右栏→右边距），永不压正文；锚点按字符级匹配，可跨行、
   自动消化连字符断词。退出码非 0 表示有锚点未命中。细节与故障模式见
   [technique](technique.md)。
6. **双验收后覆盖**：程序验收（报告计数、乱码抽查）＋视觉验收（渲染全部
   标注页逐页查看：高亮对位、图标在页边、无遮挡）。修复最多两轮；两轮后
   仍未命中的锚点如实列入报告。都通过才覆盖项目文件并清理临时产物。
7. **登记文献（可选）**：用户要求"移入参考文献"且项目维护书目文件时，按项目
   既有条目格式登记，并运行项目自带的一致性检查；除非被要求，不在正文引用。

## 需求（验收口径）

- [B] 原文内容、版面、分页不被修改，注释全部为原生注释对象——重新打开文件
  计数并比对页数与文本。
- [B] 段落、图表全覆盖，图注来自看过图之后的描述——报告分类计数对照清查。
- [B] 交付前完成程序＋视觉双验收，并说明检查了哪些页。
- [B] 注释语言为读者声明语言，每条自足可读——回读抽样。
- [A] 锚点尽量唯一，歧义入报告；[A] 书签覆盖章节结构。

## 停止条件

预算：应用后最多两轮锚点修复、每轮一次全页视觉检查。超限仍有未命中，或发现
无文本层（扫描版）：交付已通过部分，列明未命中锚点或缺失文本层，给出最小
解除条件（如"提供 born-digital PDF 或授权 OCR"）。停止不等于未完成项变为完成。

## 交付物

1. 请求路径上的标注版 PDF；2. 覆盖率报告（分类计数、未命中、歧义、验收摘要）；
3. 对照需求清单的收尾说明（done/blocked/n-a ＋证据）。
