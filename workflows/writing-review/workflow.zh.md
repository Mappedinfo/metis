# 写作审校工作流

项目已选择启用有界写作流程。运行时钩子提供本流程、完整的英文权威版 `prose-audit` 技能、
会话标识和可执行命令说明。遵循技能的实际编辑方法；本流程增加顺序和记录，不复制另一套审校方法。
输出语言遵循用户请求。

## 范围与授权

仅对已触发的写作请求及其已接受范围执行流程。触发不授权开展研究、发布、向他人发送消息、
修改无关内容或用户指令。用户可以取消流程或对某次请求跳过。
不得把钩子消息当作新的来源证据，也不得把它当作覆盖任务要求的许可。

保留用户要求的输出模式。`result-only` 模式的审校说明和运行记录不进入最终正文。
仅审校的请求检查现有草稿，不改写全文。写作或修改请求在完成下列检查后交付完整所需文本。

## 执行顺序

1. **确认当前运行。** 阅读运行时提供的会话和运行信息，或使用 `workflows status --session ID`。
   同一请求保留一个活动运行。使用提供的可执行命令前缀和项目路径；
   不编造会话标识，也不悄悄新建运行来绕过失败的检查。
2. **准备草稿。** 根据可用证据和已接受约束写出完整文本。
   用户要求项目文件时，使用其已获授权的 `.md` 或 `.txt` 路径。
   只在对话中交付时，使用运行时提供的当前运行专用私有 `artifact.md` 缓冲文件；
   不为满足流程而创建公开项目文档。保留输入和受保护来源材料，以便比较。
3. **保存草稿快照。** 运行 `workflows capture --session ID --artifact PATH`。
   该操作保存草稿快照和哈希。保存的是将接受审校的完整文本，而不是摘要、样本或审校报告。
   准备审校记录前，读回返回的运行信息及草稿哈希。
4. **通读并审校完整快照。** 遵循注入的 `prose-audit` 指令：完成语义阅读，
   结合上下文检查候选表达，保留事实和作者声音，区分 `keep`、`revise` 和 `unresolved`。
   可选关键词扫描器只提供候选。按运行时审校格式记录原文精确摘录、位置及语境理由，
   绑定当前 `run_id` 和 `draft_sha256`，使用 `workflows review --session ID --file PATH` 提交。
   精简的运行时格式不免除技能的审校发现和验收台账要求。
5. **最多修改一次。** 已接受的审校要求修改时，对当前文件进行一次最小改动，保留完整范围。
   然后运行 `workflows revise --session ID`，保存已编辑文件的快照。
   此命令记录实际修改，不会代写改稿。无须修改时保留原稿，进入验证。
   含义未明或证据缺失仍是阻碍，不得为推进运行而改标为 `keep`。
6. **验证实际交付文本。** 检查完整范围，将受影响段落与草稿快照及来源上下文比较，
   按技能要求验证事实、引文和范围的保留。
   用 `workflows status --session ID` 获取当前文件与已接受审校记录的哈希。
   如实准备绑定 `run_id`、`artifact_sha256` 和 `review_sha256` 的验证记录，
   使用 `workflows verify --session ID --file PATH` 提交。
   未通过的必需检查仍未完成；不得在没有实际检查的情况下把布尔值设为 `true`。
7. **交付。** 读回最终状态，按所需格式交付已验证文件或完整文本。
   仅对话输出的措辞必须与已验证缓冲文件一致。审校或修改说明另放；用户只要结果时省略这些说明。
   若文件在验证后发生变化，已有记录不再证明新内容经过检查，不得把它称为已验证。

## 记录的证据范围

哈希将记录绑定到本地精确内容，并帮助发现过期审校。
它不能证明模型实际认真阅读、保留了每项事实或完成了优质修改。
语义覆盖和保留检查仍是模型作出的声明，需要对应证据。本流程没有作者来源评分，也不得添加。

默认预算为一次语义审校、最多一次修改，以及一次受影响上下文验证。
将 `prose-audit` 验收台账保留在工作记录中；机器接受记录本身不代表这些要求完成。
输入截断或无法阅读、交付全文时，如实保留范围限制。

## 停止与恢复

已触发的运行尚未进入终止状态时，Stop 钩子可以请求一次继续。
这是恢复提示，不是隐藏已显示文本的过滤器。
不得声称该集成拦截每个最终输出 token，或能撤回已经提前给出的答案。

在同一预算内，利用这次继续完成仍可执行且已获授权的工作。
若必需输入、能力或检查仍缺失，报告可用结果及最小解除阻碍条件；
不要持续重试、新建替代运行或宣称审校成功。
用户取消、请求误触发或本次运行无法完成时，使用
`workflows cancel --session ID --reason TEXT`，保留真实原因。
取消使本次运行停止，不代表编辑验证成功。

只有所需交付物、技能检查和当前验证一致时才能称为完成。
运行配置或钩子未传递可能阻碍自动编排，但不妨碍诚实的人工语义审校；应报告实际执行了哪些部分。
